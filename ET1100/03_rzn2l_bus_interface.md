## 3.1 なぜ「非同期 8/16bit µController インタフェース」なのか

RZ/N2L の外部バス（FSP 上は **BSC = Bus State Controller**、API 名 `r_bsc` /
`external_bus_api`）は、`bsc_memory_type_t` として **`BSC_MEMORY_TYPE_SRAM`（Normal space）**
のみをサポートします（`r_bsc.h`）。つまりユーザーが言う「SRAM バス」は、RZ/N2L の
外部バスを SDRAM モードではなく通常の非同期 SRAM/NOR 型メモリ空間として使う、という意味です。
これは以下の点で ET1100 の **PDI 8（16bit 非同期 µC）/ PDI 9（8bit 非同期 µC）** と
自然に対応します。

| 項目 | RZ/N2L BSC (SRAM空間) | ET1100 非同期 8/16bit µC PDI |
|---|---|---|
| バスクロックの外部出力 | なし（非同期） | 不要（非同期、`BUSCLK` を使わない） |
| データ幅 | 8/16bit（`external_bus_data_bus_width_t`。**32bit は RZ/N2L 非対応**: `BSP_FEATURE_BSC_32BIT_DATA_BUS_WIDTH_SUPPORTED=0`） | 8bit(PDI9) / 16bit(PDI8) |
| チップセレクト | CS0, CS2, CS3, CS5（RZ/N2L で利用可能な4本、`BSP_FEATURE_BSC_NOR_CSx_BASE_ADDRESS`） | `CS` 入力1本 |
| 外部ウェイト機能 | あり（`external_bus_external_wait_t`、CS単位でON/OFF可） | `BUSY`（ESC→µC）出力あり |
| アドレス/データ | 分離（デマルチプレクス） | 分離（デマルチプレクス）必須 |

一方、**同期 8/16bit µC PDI（PDI 10/11）** は `BUSCLK` の供給が必要であり、
RZ/N2L の BSC の非同期 SRAM 空間はバスクロックを外部出力しないため、**同期 PDI は
選ばないでください**。

## 3.2 ET1100 側の信号（非同期 8/16bit µC PDI）

出典: HW 6.4.1 Table 70。

| 信号 | 向き（ET1100視点） | 説明 | 極性（既定・EEPROM設定可） |
|---|---|---|---|
| `CS` | IN | チップセレクト | 通常 active low |
| `ADR[15:0]` | IN | アドレスバス | active high |
| `BHE` | IN | バイトハイイネーブル（16bit時のみ） | 通常 active low（`0x0150[4]`で切替可） |
| `RD` | IN | 読み出しストローブ | 通常 active low（`0x0150[7]`で切替可） |
| `WR` | IN | 書き込みストローブ | 通常 active low |
| `DATA[15:0]` または `DATA[7:0]` | BD | データバス | active high |
| `BUSY` | OUT | ET1100 がビジー中であることを示す（＝ホストが待つべき信号） | 既定 active low・プッシュプル（EEPROM word A1[3:0]で設定） |
| `IRQ` | OUT | 割り込み要求 | 既定 active low（設定可） |
| `EEPROM_LOADED` | OUT | EEPROM 読込完了・PDI 動作可能 | active high（プルダウン必須） |

ポイント：

- **`RD`/`WR` はそれぞれ1本ずつ**（バイトレーンごとの書き込みストローブは持たない）。バイト単位の
  書き分けは `ADR[0]` と `BHE` の組み合わせで行います（HW Table 72）。
- **`BUSY`** はいわゆる WAIT/READY 信号です。CS アサート後 最大15ns で駆動され、
  内部処理が終わると解除されます（HW Table 73）。**ホストはこの信号でバスサイクルを
  延長するのが最も安全な設計**です（3.5節）。
- **BHE/RD/BUSY/IRQ の極性・ドライバ形式（プッシュプル/オープンドレイン）は EEPROM で設定**します
  （`0x0150`、HW/Section II 2.6.6.4）。RZ/N2L 側の対応ピンの極性・プルアップ有無に合わせて
  EEPROM 設定を選んでください。

## 3.3 RZ/N2L 側の信号（BSC・SRAM 空間、CS0/2/3/5）

`rz-fsp/rzn/rz/fsp/src/bsp/mcu/rzn2l/bsp_override.h` のピン機能定義（IOPORT PFC）から
確認できる、BSC の SRAM/NOR 用信号一覧（抜粋）：

| 信号 | 役割 |
|---|---|
| `A0`〜`A25` | アドレスバス（最大26bit） |
| `D0`〜`D15` | データバス（16bit） |
| `CS0`, `CS2`, `CS3`, `CS5` | チップセレクト（RZ/N2L で NOR/SRAM 用に使える4本。`BSP_FEATURE_BSC_NOR_CS0/2/3/5_BASE_ADDRESS`） |
| `RD` | 読み出しストローブ |
| `WE0_DQMLL` | 書き込みストローブ（バイトレーン0＝下位バイト D[7:0]用。SDRAM 時は DQM 兼用） |
| `WE1_DQMLU` | 書き込みストローブ（バイトレーン1＝上位バイト D[15:8]用。SDRAM 時は DQM 兼用） |
| `RD_WR` | 読み/書き方向信号（`RD` とは別ピン。バスモードによって使い分けと推測されるが、本リポジトリの情報のみでは詳細未確認） |
| `WAIT` | 外部ウェイト入力（`external_bus_external_wait_t` に対応） |
| `AH` | アドレスホールド関連信号（詳細は RZ/N2L マニュアル要確認） |
| `RAS`, `CAS`, `CKE`, `CKIO`, `BS` | SDRAM/バースト用信号（**SRAM 用途では通常未使用**） |

CS ごとのベースアドレス（`bsp_feature.h`、いずれも 256MB 空間、CS0のみミラー領域あり）：

| CS | ベースアドレス |
|---|---|
| CS0 | `0x70000000` |
| CS2 | `0x74000000` |
| CS3 | `0x78000000` |
| CS5 | `0x7C000000` |

## 3.4 バス幅・バイトイネーブルの不一致とその解決方針

ここが本接続の一番の勘所です。

- ET1100 は **単一の `RD`/`WR` + `ADR[0]`/`BHE` の組み合わせ**でバイト/ワードアクセスを
  区別します（HW Table 71/72）。
- RZ/N2L の BSC は **バイトレーンごとの書き込みストローブ `WE0#`/`WE1#`**（+ 共通の `RD`）という、
  一般的な Renesas RX/SH 系バスコントローラでおなじみの方式に見えます（信号名から推測。
  `RD_WR` という別ピンも存在するため、RZ/N2L のバスコントローラが複数のバスプロトコル
  モードを持つ可能性があります。**この点は RZ/N2L のハードウェアマニュアルで
  実際の動作モードを確認してください**）。

この「バイトイネーブルの方式が違う」問題に対して、2つの選択肢があります。

### 方式A（推奨）: 常時16bitアクセスに統一し、`ADR[0]`と`BHE`をGNDに固定

ET1100 のデータシートには、**まさにこのケース**（バイトアドレッシングを持たない16bit
µController/DSP との接続）を想定した公式の接続例があります（HW 6.4.8、Figure 31）。

- ET1100 の `ADR[0]` と `BHE` を **GND に固定**する
- ET1100 は常に「16bitアクセス」として動作する（`ADR[0]=0, BHE=0` は Table 72 の
  「16 bit access（low and high byte）」に該当）
- ET1100 の `ADR[15:1]` に、ホスト側の「ワードアドレス」を接続する（＝**ET1100 のレジスタ
  アドレスは 2 で割った値**をホストのアドレスバスに出す。HW 6.4.8 の注記どおり）

RZ/N2L 側に当てはめると：

- RZ/N2L の `A1`〜`A16` を ET1100 の `ADR[0]`〜`ADR[15]` に接続する（**1ビットずれる**ことに注意。
  RZ/N2L の `A0` は ET1100 には接続しない）
- ET1100 の `ADR[0]`、`BHE` は GND 固定
- **書き込みストローブ**: RZ/N2L の `WE0#` と `WE1#` を **2入力ANDゲートで結合**し、
  その出力を ET1100 の `WR` に接続する（提案）。
  - 理由: ソフトウェアが必ず 16bit 境界に揃った `uint16_t` アクセスしかしない設計にすれば、
    `WE0#`/`WE1#` は常に同時にアサートされるため AND ゲートの出力は通常の `WR` と同じに
    なります。**万が一ソフトウェアや最適化の副作用で 8bit（片バイトのみ）アクセスが
    発行されてしまっても、AND ゲートにより書き込みパルスが生成されず、意図しない
    バイトのみの書き込み（隣接レジスタ破壊）を未然に防げます。**
  - RZ/N2L の外部バス設定は **データ幅16bit（`EXTERNAL_BUS_DATA_BUS_WIDTH_16BIT`）**にします。
- **読み出しストローブ**: RZ/N2L の `RD` を ET1100 の `RD` にそのまま接続（読み出しは
  バイトレーン制御が不要なため単純接続でよい）。
- **ウェイト**: RZ/N2L の `WAIT` ピンを ET1100 の `BUSY` に接続（3.5節）。

この方式のソフトウェア側の制約：

- ET1100 の全レジスタ・RAM は **必ず `volatile uint16_t*`（または偶数境界の `uint32_t*`）で
  アクセスする**。`volatile uint8_t*` でのアクセスは（コンパイラが実際に1バイトの
  バス転送を生成した場合）AND ゲートにより書き込みが成立しない可能性があるため使わない。
  8bit相当のレジスタ値は、含まれる16bit語を読んでからシフト/マスクで取り出す。
- ET1100 のレジスタマップは実際にはほぼ**2バイト単位で意味のある値がペアになるよう
  設計されている**ことが多いです（例：`0x0140` PDI0 control と `0x0141` ESC configuration A0 は
  隣接する別々の意味を持つレジスタ）。**1バイトだけ意図的に変更したい場合でも、
  必ずペアとなる16bit語ごと読み出し→該当バイトだけ書き換え→16bitで書き戻す
  （read-modify-write）**という実装ルールを徹底してください。

### 方式B: バイトイネーブル対応のグルーロジックを追加する

`ADR[0]`/`BHE` を使ったバイト単位の直接アクセスをハードウェアレベルで実現したい場合、
RZ/N2L の `WE0#`/`WE1#`（および `A0`）から ET1100 の `BHE`・`ADR[0]` を導出する
追加の組み合わせ回路（またはRZ/N2Lの別のバスモード設定）が必要です。方式Aに比べて
配線・検証コストが増える一方、メリットは「ソフトウェアが read-modify-write を
意識しなくてよくなる」程度です。**プロセスデータ（周期通信のペイロード）は
アプリケーション側でメモリレイアウトを自由に設計できる**ため、通常は方式Aの制約は
実運用上ほとんど問題になりません。特別な理由がなければ**方式Aを推奨**します。

## 3.5 ウェイト（BUSY/WAIT）設計 — 最重要ポイント

ET1100 の内部処理時間は固定ではありません（HW Table 73、抜粋）：

| アクセス種別 | 内部処理時間（代表値） | 直前に書き込みがあった場合の最悪値 |
|---|---|---|
| 8bit 読み出し | 235 ns | 435 ns |
| 16bit 読み出し | 315 ns | 575 ns |
| 8bit 書き込み | 200 ns | — |
| 16bit 書き込み | 280 ns | — |

この時間は `BUSY` 信号の長さとして現れます。RZ/N2L のバスクロック周期にもよりますが、
**固定ウェイトサイクル数の設定だけでこの最悪値（最大575ns）を常にカバーしようとすると、
バスクロックが速いほど非常に多くのウェイトサイクルが必要**になり、`bsc_access_wait_cycle_t`
の最大値（24サイクル）や `idle_cycle` の組み合わせで足りない可能性があります。

**推奨する設計方針**：

1. ET1100 の `BUSY` 出力を RZ/N2L の外部ウェイト入力ピン（`WAIT`）に接続する
2. RZ/N2L 側の `external_bus_cfg_t.external_wait_en` を `EXTERNAL_BUS_EXTERNAL_WAIT_ENABLE` にする
3. これにより **ET1100 が実際にビジーである間だけバスサイクルが延長**され、
   最悪値を固定サイクルで見積もる必要がなくなり、平均的なアクセス速度も向上します
4. `BUSY` の極性（既定 active low・プッシュプル、HW 2.6.6.4／Section II）と、
   RZ/N2L の `WAIT` ピンが要求する極性・タイミング（レベルサンプルかエッジか、
   何クロック分のセットアップが必要か等）が一致するかを **RZ/N2L のハードウェア
   マニュアルで確認**し、必要なら EEPROM 側の `BUSY` 極性設定（EEPROM word A1[1:0]）を
   合わせてください。

**フォールバック（配線を増やしたくない場合）**：`WAIT` を接続せず、固定ウェイトサイクル
（`bsc_access_wait_cycle_t` の `read_access_wait_cycle` / `write_access_wait_cycle`）
だけで賄う場合は、**実際に使用する外部バスクロック周期を確認した上で**、

```
必要ウェイトサイクル数 = ceil(575 ns ÷ バスクロック周期[ns])   … 読み出し最悪値
必要ウェイトサイクル数 = ceil(280 ns ÷ バスクロック周期[ns])   … 書き込み
```

を計算し、`BSC_ACCESS_WAIT_CYCLE_*` と CS 前後の `cs_pulldown_lead`/`cs_pullup_lag`、
必要であれば `w_r_w_w_idle_cycle` 等を組み合わせて確保してください。**この方式は
バスクロックが速いほど不利になるため、可能な限り方式1（WAIT接続）を推奨します。**

## 3.6 アドレスデコード（ソフトウェアからの見え方）

方式Aを採用した場合、RZ/N2L の CSn 空間ベースアドレスを `ET1100_BASE` とすると：

```c
#include <stdint.h>

#define ET1100_BASE   (0x70000000u)   /* 例: CS0 を使う場合 */

/* ET1100 のバイトアドレス reg_addr（偶数）にある 16bit レジスタへのアクセス */
static inline uint16_t et1100_reg_read16(uint32_t reg_addr)
{
    volatile uint16_t *p = (volatile uint16_t *)(ET1100_BASE + reg_addr);
    return *p;
}

static inline void et1100_reg_write16(uint32_t reg_addr, uint16_t value)
{
    volatile uint16_t *p = (volatile uint16_t *)(ET1100_BASE + reg_addr);
    *p = value;
}

/* 1バイトだけを安全に書き換える例（read-modify-write） */
static inline void et1100_reg_write8(uint32_t reg_addr, uint8_t value)
{
    uint32_t aligned = reg_addr & ~1u;
    uint16_t word    = et1100_reg_read16(aligned);
    if (reg_addr & 1u)
    {
        word = (uint16_t)((word & 0x00FFu) | ((uint16_t)value << 8));
    }
    else
    {
        word = (uint16_t)((word & 0xFF00u) | value);
    }
    et1100_reg_write16(aligned, word);
}
```

複数バイト（プロセスデータや FMMU/SM 設定など)をまとめて転送する場合は、
`uint16_t` 単位でループするか、RZ/N2L 側が16bit幅CS空間への `uint32_t` アクセスを
2回の16bitバスサイクルに自動分解してくれるかどうかを確認した上で使ってください
（BSC がバス幅より広いCPUアクセスをどう分解するかは RZ/N2L マニュアル要確認）。

## 3.7 リセット・EEPROM に関する配線上の注意（再掲）

- ET1100 の `RESET` はオープンコレクタです。RZ/N2L 自身のリセット信号／リセットIC出力も
  同じネットにワイヤードOR接続することを検討してください（`02_et1100_overview.md` 2.5節）。
- ET1100 の `EEPROM_CLK`/`EEPROM_DATA` は ET1100-EEPROM専用の I²C バスです。RZ/N2L の
  I²C ペリフェラルをこのバスに接続する設計は基本的に不要（EEPROM の内容を書き換えたい場合は
  ET1100 をリセット状態にした上で in-circuit programming する運用になります、HW 第8章）。
- ET1100 の PDI 関連ピン（`ADR/DATA/CS/RD/WR/BUSY/IRQ/EEPROM_LOADED`）は、
  **EEPROM 読み込みが完了するまで駆動されません**。`EEPROM_LOADED` を使う場合は
  プルダウン抵抗を付けてください（HW 6.4.7）。

## 3.9 CPU キャッシュ／MPU 属性とメモリ順序（見落としやすいが重大）

RZ/N2L は Arm コア（Cortex-R/A 系）を搭載しており、**外部バス（BSC）で見えるメモリ空間も
デフォルトではキャッシュ可能／投機アクセス可能な属性になっている可能性があります**。
ET1100 のようなハードウェア（読むたびに状態が変わる／書いた副作用がある）を
メモリマップドレジスタとして扱う場合、これは致命的な不具合の原因になります。

- **CS0/CS2/CS3/CS5 の ET1100 用アドレス範囲は、MPU（Memory Protection Unit）設定で
  必ず「Device」または「Strongly-ordered」相当（非キャッシュ・非バッファ・投機アクセス禁止）に
  設定してください。** 通常のキャッシュ可能な Normal メモリのままだと、
  - `BUSY` を見ながら読んだつもりでも、実際には CPU/キャッシュに残っていた古い値を
    読んでしまう（レジスタの状態変化に気づけない）
  - 連続する `AL event request` の読み出しがコンパイラや CPU のアウトオブオーダー実行で
    順序を保証されない
  - 書き込みがライトバッファに滞留し、実際に ET1100 に届くタイミングが予測できない
    といった問題が発生し得ます。
- `volatile` 修飾はコンパイラに対する最適化抑制（アクセスの省略・並べ替え禁止）の指示であり、
  **CPU のキャッシュやアウトオブオーダー実行、外部バスのバッファリングまでは制御しません**。
  MPU 属性を正しく設定することと `volatile` を使うことは、どちらも必要で片方だけでは不十分です。
- 実際に使用する Arm コア（Cortex-R52 / Cortex-A55 等、コア種別は RZ/N2L のドキュメントを
  確認）の MPU/MMU 設定方法は本リポジトリの範囲外です。RZ/N2L のハードウェア
  マニュアルおよび使用する Arm コアのアーキテクチャリファレンスマニュアルで、
  該当アドレス範囲を Device memory として設定する手順を確認してください。
- 念のため、レジスタアクセスの前後に `DSB`（Data Synchronization Barrier）等の
  メモリバリア命令を入れる設計にしておくと、MPU 設定の不備があっても実害が出にくくなります
  （ただし正しい MPU 設定の代替にはなりません）。

## 3.10 マルチコア・DMA 利用時の注意

- RZ/N2L がマルチコア構成の場合、**ET1100 の CS 空間へアクセスするコアを1つに限定する**か、
  複数コアからアクセスする設計にするならミューテックス等で排他制御してください。
  特に `esc_read16`/`esc_write16` のようなレジスタアクセス関数を複数コアから
  無秩序に呼ぶと、`RD`/`WR` バスサイクルが競合したり、`BUSY` の状態を取り違えたりする
  リスクがあります。
- DMA コントローラでこの CS 空間を直接読み書きする設計（例：プロセスデータの一括転送）は、
  **DMA コントローラが外部バスの `WAIT`（BUSY 由来のウェイト挿入）を正しく認識できるか**を
  事前に確認してください。認識できない場合、ET1100 がまだ処理中のデータを DMA が
  読み書きしてしまう可能性があります。確証が持てない場合は、まず CPU による
  読み書き（レジスタアクセス）で実装し、性能要件が満たせない場合にのみ DMA 化を検討する
  順序を推奨します。

## 3.11 設定・検証のチェックリスト

- [ ] ET1100 EEPROM の PDI 種別を `0x08`（16bit非同期）または `0x09`（8bit非同期）に設定した
- [ ] （方式Aの場合）EEPROM の PDI 拡張設定で `BHE`/`ADR[0]` 固定運用に矛盾がないか確認した
- [ ] `BUSY` の極性・ドライバ種別（push-pull/open-drain、active high/low）を EEPROM で設定し、
      RZ/N2L の `WAIT` ピン仕様と一致させた
- [ ] RZ/N2L の BSC を対象 CS（CS0/2/3/5 のいずれか）・SRAM(Normal space)・データ幅16bit で設定した
      （CS0 の場合の具体的なレジスタ値・サンプルコードは
      [../../rzn2l/docs/07_bsc_cs0_et1100_register_setup.md](../../rzn2l/docs/07_bsc_cs0_et1100_register_setup.md)）
- [ ] `external_wait_en` を有効化し、`WAIT`⇔`BUSY` を配線した（または固定ウェイトサイクルを
      実クロックから計算して設定した）
- [ ] アドレスの1ビットオフセット（RZ/N2L `A(n+1)` → ET1100 `ADR(n)`）を配線・アドレスマップ双方で
      整合させた
- [ ] ソフトウェアが `volatile uint16_t*` 以外でこの CS 空間にアクセスしていないことをコードレビューで確認した
- [ ] **ET1100 用アドレス範囲を MPU で Device（非キャッシュ・非バッファ）属性に設定した**
- [ ] （マルチコア構成の場合）ET1100 アクセスの排他制御方針を決めた
- [ ] （DMA を使う場合）DMA コントローラが外部ウェイト信号を認識できることを確認した
- [ ] RESET ネットを ET1100・PHY・RZ/N2L で共有する設計にした（またはしない場合の理由を明記した）
- [ ] RZ/N2L ハードウェアマニュアルの外部バスインタフェース章で、上記のピン意味・タイミングを
      最終確認した

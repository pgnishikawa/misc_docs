# メモリ選択と速度比較（TCM / SYSRAM / LPDDR4）

[← README（目次）へ戻る](README.md)

「速度が必要な処理は DDR ではなく SYSRAM または TCM に置きたい」という要件と、「R52+TCM と A55+SYSRAM のどちらが速いか」という問いに対する整理。
出典: 「3. Cortex-R52」表 3.2 p.180-181、「44. システムSRAM (SYSRAM)」44.1 概要 p.2931、「57. LPDDR4 SDRAMサブシステム」57.6 p.3742、「1.2 機能の比較」「7. クロック発生回路」。

## 結論を先に（★処理内容によって答えが変わることに注意）

「どちらが速いか」は **ワーキングセット（コード＋データ）が最速メモリ階層に収まりきり、かつ追い出されずに常駐し続けるか** で答えが逆転する。単純に「R52+TCM が常に一番速い」わけではない。

- **メモリアクセスが絡む処理・タイミング保証が必要な処理**（周期制御、割り込みハンドラ、モーション制御ループ等）→ **Cortex-R52 が自分の TCM（ATCM/BTCM）にアクセスするケースが最速・最も決定的（jitter が最小）。** バス調停もクロック跨ぎも一切なく、常に一定レイテンシ。これが「勝つ」の中身であり、"常にどんな処理でも数値上最速" という意味ではない。
- **メモリアクセスがほとんど発生しない純計算処理**（小さいホットループがコア内で完結する等）→ **A55 がキャッシュ（L1/L3）にワーキングセットを載せてウォームに保てるなら、より高いコアクロック（最大 1200 MHz vs TCM 実行時の R52 最大 1000 MHz）とより高性能なコアマイクロアーキテクチャにより、A55 の方が数値上速くなり得る。** ただしキャッシュは「保証」ではなく「結果的にそうなることが多い」ものなので、確定的な最悪値保証が要る用途には向かない。
- **Cortex-A55 には TCM が存在しない。** A55 で DDR を避けたい場合の選択肢は実質 **SYSRAM**（または L1/L3 キャッシュに載せる）。
- **「A55 + SYSRAM」と「R52 + SYSRAM」を比べた場合**: SYSRAM 自体の物理レイテンシ（250 MHz ドメイン、約 8〜12 ns）はどちらのコアからアクセスしても**同一**。差が出るとすれば「そのレイテンシをどれだけコア側で隠せるか」（A55 の方が高クロック・高性能で有利になりやすい）と「そもそも SYSRAM への実アクセス頻度をキャッシュでどれだけ減らせるか」（A55 は L1 32KB×2＋共有L3 1MB、R52 は L1 16KB×2 のみで L3 なし、なので A55 が有利になりやすい）の 2 点。**A55 の方が速いという推測は妥当だが、これはマニュアルに実測データがあるわけではなく、一般的なアーキテクチャ知識からの推論**である点に注意（本チップ向けの実測ベンチマークは本マニュアルの範囲外）。
- **「命令フェッチ速度が実行速度を支配する」は条件付きで正しい**: ワーキングセットが最速階層（TCM／ウォームなキャッシュ）に収まり常駐し続けるならフェッチはボトルネックにならず、**コア自体の性能（クロック・発行幅・IPC）が支配的**になる（この領域は A55 が有利）。ワーキングセットが溢れる、あるいはアクセスパターンが不規則でキャッシュに乗り切らない場合に、初めて**メモリアクセス速度が支配的**になる（この領域で TCM の一貫した速さと決定性が効く）。

### この chip の設計意図から見た実務的な結論

RZ/N2H は産業用途（モータ制御・エンコーダ・タイマ多数）向けに、**低レイテンシ周辺バス (LLPP) 上のタイマ／PWM／ADC／エンコーダ群に R52 CPU0/CPU1 を優先アクセスさせる**設計になっている（[01_overview.md](01_overview.md) のブロック図、13.4.1 のアービトレーション記述）。これは「R52+TCM で締切厳守のリアルタイム制御ループを回し、A55 はキャッシュ＋高クロックを活かしたアプリケーション処理／通信スタック等の平均スループット重視の処理を担う」という役割分担が、ハードウェア設計の時点で既に示唆されている、と読める。「どちらが速いか」という問いへの実務的な回答は、**速さそのものより「その処理にとって重要なのは平均スループットか、最悪値の保証か」で置き場所を決める**、ということになる。

## 1. 各メモリの仕様比較

| メモリ | 動作クロック | アクセスレイテンシ | 専有／共有 | バス調停 | クロック跨ぎ | 容量 | 排他アクセス |
|--------|-------------|---------------------|-----------|---------|-------------|------|-------------|
| **ATCM**（R52 各コア専用）| **CPU コアクロックと同期**（500/1000 MHz、`MDWn`依存）| **0 wait @500MHz／1 wait @1000MHz**（＝実時間で常にほぼ一定、約 2 ns）| コアごとに専有（自コアからは直結）| **なし** | **なし** | 512 KB/コア | — |
| **BTCM**（R52 各コア専用）| CPU コアクロックと同期 | **0 wait（周波数によらず常に）** | コアごとに専有 | **なし** | **なし** | 64 KB/コア | — |
| **SYSRAM** | **固定 250 MHz (PCLKH)**（CPU クロックとは無関係）| ECC有効: 読み出し**3サイクル(12 ns)**／書き込み32-128bit**1サイクル(4 ns)**、8/16bit**3サイクル(12 ns)**。ECC無効: 読み出し**2サイクル(8 ns)**／書き込み**1サイクル(4 ns)** | 全バスマスタ共有（A55/R52×2/DMAC/GMAC/USB/SDHI/LCDC/PCIE/CoreSight）| **あり**（内部メインバス、ラウンドロビン方式）| **あり**（各マスタのコアクロック→250MHzへの同期）| 2 MB（512KB×4）| **不可**（CPU の排他命令使用禁止）|
| **L1 キャッシュ**（A55 各コア専用）| コアクロックと同期（600/1200 MHz）| ヒット時 数サイクル（実装依存、非公開）| コアごとに専有 | なし | なし | I/D 各 32 KB | — |
| **L3 キャッシュ**（A55 クラスタ共有）| コアクロックと同期 | ヒット時 数サイクル〜十数サイクル | クラスタ内 4 コアで共有・コヒーレント | クラスタ内調停 | なし | 1 MB | — |
| **LPDDR4 (DDRSS)** | コントローラ 800 MHz (DFICLK) ／DRAM 転送 3200 Mbps | **DRAM 自体の行アクティブ化・CAS レイテンシ（数十 ns オーダー、デバイス依存）＋ コントローラパイプライン＋マルチポート調停** の合算。加えて**定期トレーニングで 167 ms ごとに 1.6 µs 完全にアクセス不可**（表 57.34）| 全バスマスタ共有（5 AXI ポート: A0/A1/A4/R2/R3）| **あり**（重み付けラウンドロビン、優先順位緩和機能あり、57.4.2）| あり | 最大 64 Gb (8 GB) | 各ポート最大 2 トランザクションまで対応 |

> SYSRAM の「レイテンシ」欄はマニュアル記載の **RAM 自体の内部レイテンシ**（250 MHz ドメイン内）。実際に A55（最大 1200 MHz）や R52（最大 1000 MHz）から見た総レイテンシは、これに **内部バスの調停待ち＋クロックドメイン跨ぎの同期段**が上乗せされる。TCM にはこの上乗せが一切ない。

## 2. なぜ TCM が最速なのか（アーキテクチャ的理由）

- TCM（Tightly-Coupled Memory）は Cortex-R シリーズの設計思想そのもので、**CPU に直結**しており、内部バスもアービタも経由しない。「決定的（deterministic）な最悪値レイテンシ」を保証することが目的の機能。
- 本 LSI の実装でも、ATCM は **CPU コアクロックに同期**しており（500 MHz なら 0 wait、1000 MHz なら 1 wait）、実時間換算では**常に約 2 ns 前後で一定**——つまり動作周波数を上げても実アクセス時間はほぼ変わらない（wait state が追加されるだけ）。これは「バスを介さない直結メモリ」だからこそ可能な特性。
- 対して SYSRAM は「250 MHz で動く共有 SRAM」であり、A55/R52 から見れば**外部の周辺スレーブの一つ**（内部メインバス上のバススレーブ）。マニュアル 13.4.1 の記載どおり「内部メインバス A および R のアービトレーション方式はラウンドロビン方式」＝**他のバスマスタ（DMAC、GMAC、他方の CPU 等）と順番待ちが発生し得る**。
- したがって、**「R52 が自分の TCM にアクセスする」ことと「A55 が SYSRAM にアクセスする」ことは、そもそも同じ土俵で比較できるものではない**。前者は専有・直結・無調停、後者は共有・バス経由・調停あり。速度でも決定性でも前者が優位。

## 3. A55 には TCM がない、という制約

- 「1. 概要」の CPU 一覧（[01_overview.md](01_overview.md)）のとおり、Cortex-A55 の高速メモリは **L1 キャッシュ（32KB/32KB）＋ L3 キャッシュ（1MB 共有）のみ**。TCM は Cortex-R52 専用機能で A55 には実装されていない。
- そのため A55 コアで「DDR を避けて速く／決定的に動かしたい」場合の選択肢は:
  1. **SYSRAM に配置する**（本ドキュメントの主題。DDR よりは高速・低ジッタだが、R52+TCM ほどではない）
  2. **キャッシュに乗る前提でコードサイズを絞り、実行前に一度ウォームアップする**（ヒット時は非常に高速だが、割り込みや他コアのキャッシュ汚染で追い出される可能性があり非決定的）
- ハード実時間性（割り込み応答、周期制御のジッタ最小化）が目的なら、**そのタスクを R52 側に置いて TCM で実行する方が、A55+SYSRAM や A55+キャッシュより設計上シンプルかつ堅牢**。A55 側は「TCM が使えない」という制約を前提にした設計（SYSRAM 常駐 or キャッシュ運用）が必要になる。

## 4. 実装への反映（[10_amp_multicore_bringup_roadmap.md](10_amp_multicore_bringup_roadmap.md) の補足）

Phase 3 の DDR パーティション案は「全コアを DDR で動かす」前提で書いたが、**実際には速度が必要な部分だけ SYSRAM/TCM に残し、それ以外（サイズが大きい・速度要件が緩いタスクや大きなデータ）だけ DDR に置く、という混在構成が可能かつ推奨**。

| コア | 高速・決定的にしたい処理の置き場所 | 備考 |
|------|-----------------------------------|------|
| R52 CPU0 | **自分の ATCM（512 KB）／BTCM（64 KB）** | 最速・最も決定的。他コアからの干渉なし |
| R52 CPU1 | **自分の ATCM（512 KB）／BTCM（64 KB）** | 同上。CPU0 の TCM とは完全に別空間（干渉なし）|
| A55 Core0〜3 | **SYSRAM（2 MB を 4 コアで分割）** | TCM がないため次善の策。DMAC 等他マスタとの調停で R52+TCM より遅くなり得る点に注意 |
| （どのコアでも）低速許容・大容量が必要な部分 | **LPDDR4** | NORTi 本体の大部分、ログバッファ、通信バッファ等 |

- **SYSRAM は 2 MB を 4 ユニット（512 KB × 4、`SYSRAM0`〜`3`）に分かれて配置**されている（`0x1000_0000`〜`0x101F_FFFF`）。A55 の 4 コアで完全に独立させたいなら、**ユニットごとに 1 コア専用として運用**（ソフトウェア的な取り決め。ハードウェアが強制するものではない）すれば、コア間の SYSRAM 内競合は避けられるが、**DMAC/GMAC/USB/SDHI/LCDC/PCIE/CoreSight など他バスマスタとの競合は依然として起こり得る**（これらが SYSRAM にアクセスする設定にしている場合）。競合を最小化したいなら、当該他マスタの DMA 転送先を SYSRAM ではなく DDR にする、等の設計判断も検討。
- SYSRAM は **CPU からの排他アクセス命令（LDREX/STREX 系、LDXR/STXR 系）が使用禁止**（13.5.5）。A55 側で SYSRAM 上のデータに対しロックフリー同期をしたい場合は、キャッシャブル・非共有設定にした上での排他アクセス、または MBXSEM を使う。

## 5. キャッシュのアーキテクチャ（A55 / R52 の違い、TCM/SYSRAM/DDR/xSPI での有無）

出典: RZ/N2H マニュアル「2.2 構成情報」表2.2/2.3 p.177-178、「3.2 構成情報」表3.1/3.2 p.180-181、「13.5.5 排他的アクセスの制限事項」p.527、「44.5.4 排他的アクセス」p.2942、「13.5.4 Cortex-R52のAXISインタフェースを介したTCMアクセス」表13.15 p.526、および Arm 公式ドキュメント `arm/cortex_r52_trm_r1p3.pdf`／`arm/cortex_r52_programmers_guide.pdf`／`arm/cortex_a55_trm_r2p0.pdf`（`arm/README.md` に一覧・入手元）。
**TCM がキャッシュを経由しない点、R52 コア間にコヒーレンシが無い点は、Arm 公式の Cortex-R52 Programmer's Guide に明記されているのを確認済み**（後述、直接引用付き）。

### 5.1 A55 と R52 のキャッシュ構成の違い

| 項目 | Cortex-A55（×4）| Cortex-R52（×2）|
|------|------------------|-------------------|
| L1 命令キャッシュ | **32 KB/コア、パリティ保護** | **16 KB/コア、ECC 保護** |
| L1 データキャッシュ | **32 KB/コア、ECC 保護** | **16 KB/コア、ECC 保護** |
| L2 キャッシュ | **なし**（表2.2に明記。本チップは構成オプションとして意図的に 0）| 概念なし（Armv8-R にコア固有 L2 という区分がそもそも存在しない）|
| L3／共有キャッシュ | **1 MB、4 コアで共有・ECC 保護**（DSU 経由、ACE でハードウェアコヒーレント）| **なし** |
| アドレス変換方式 | **MMU**（仮想→物理、ページテーブル）| **MPU**（物理アドレスのみ、2 段: EL2 用 24 領域＋EL1 用 24 領域）|
| コア間コヒーレンシ | クラスタ内 4 コアは ACE でハードウェアコヒーレント | **CPU0/CPU1 間にハードウェアコヒーレンシなし**（DCLS も本チップは非サポート）|
| A55 ⇔ R52 間 | ハードウェアコヒーレンシなし（[10]でも既述）| 同左 |

- A55 は「L2 なし・L3(1MB共有) あり」という、一般的な DynamIQ A55 実装（コアごとに L2 を持つことが多い）とは異なる構成。単体コアのキャッシュ容量という意味では R52 の L1(16KB×2) より大きい（32KB×2＋共有L3の恩恵）ため、キャッシュ面でも A55 が有利になりやすい。
- R52 の L1 は A55 より小さいが **すべて ECC 保護**（A55 の I キャッシュはパリティのみ）。R52 はもともと安全性・実時間性重視の設計であり、キャッシュ自体よりも TCM（後述）が実時間性能の主役。

### 5.2 A55 の L1 キャッシュアクセス vs R52 の TCM アクセス、どちらが速いか

**「1 回のヒットアクセス」と「実用プログラムでの平均・最悪値」で答えが変わる。**

| | クロック | レイテンシ | 実時間換算 |
|---|---|---|---|
| R52 ATCM | 500/1000 MHz | 0 wait(500MHz)／1 wait(1000MHz) = 1〜2 サイクル（マニュアル明記）| 約 1〜2 ns |
| R52 BTCM | 500/1000 MHz | 0 wait（周波数によらず常に、マニュアル明記）| 約 1〜2 ns |
| A55 L1（命令/データ）| 600/1200 MHz | **本マニュアルに記載なし**。Arm の一般公開情報ではヒット時おおむね 2〜4 サイクル程度（RZ/N2H 固有の実測値ではない）| 推定 約 1.7〜3.3 ns（推測）|
| （参考）A55 **L3**（共有 1MB、DSU）| DSU クロック 500/1000 MHz | **`L3_DATA_RD_LATENCY = 2` サイクル、`L3_DATA_WR_LATENCY = 1` サイクル**（表 2.3 DSU 構成オプションに明記）| 約 1〜2 ns |

- L1 自体のレイテンシは本マニュアルに記載がない（Arm 非公開／一般公開情報の領域）。ただし **L1 より遅いはずの L3 の読み出しレイテンシが 2 サイクルとマニュアルに明記**されており、L1 はそれよりコアに近く低レイテンシのはずなので、**L1 ヒットは R52 の TCM とほぼ同じオーダー（数 ns 以下）**、クロックが高い分わずかに有利にすらなり得る、と推測できる。
- **しかし「ヒットし続けられるか」がまったく違う。** R52 の TCM は **576 KB（ATCM 512KB + BTCM 64KB）全体が 100% 保証で常にこの速さ**。一方 A55 の L1 命令キャッシュは **わずか 32 KB** で、追い出し（他コードの実行、割り込み等）により随時ミスが発生する。実用的なファームウェア（NORTi＋アプリ）は通常 32 KB よりはるかに大きいため、**実行中のコードの一部は常に L1 に収まりきらずミスし続ける**。ミス時は L3（2 サイクル＋クラスタ内調停）→ SYSRAM（3 サイクル=12ns＋バス調停）→ 最悪 DDR（数十 ns＋調停）まで探しに行くことになり、ペナルティは TCM の数十〜100 倍規模になり得る。

| 比較軸 | 勝者 |
|--------|------|
| 1 回のヒットアクセスの絶対速度 | ほぼ互角、わずかに A55 が有利な可能性（クロックが高いため。ただし A55 の正確な L1 レイテンシは非公開）|
| 実用的なプログラムサイズでの平均速度 | **R52+TCM が優位**（576 KB 全体が「常にヒット」扱いになるため、ミスによる速度低下が原理的に起きない）|
| 最悪値・ジッタ（決定性） | **R52+TCM が圧倒的に優位**（キャッシュ追い出しという概念自体がない）|

結論: 「A55 の L1 キャッシュは R52 の TCM と同等かそれ以上に速いことがあるが、それは "当たった瞬間" の話であり、容量が 32 KB しかないため実際のプログラム全体を通してその速さを維持できない。TCM は 576 KB という実用的なサイズを常に最速状態に保てる」という点が本質的な違い。

### 5.3 TCM / SYSRAM / DDR / xSPI で「キャッシュが効くか」

| メモリ | ハードウェア的にキャッシュを経由するか | A55 でキャッシュ可能か | R52 でキャッシュ可能か |
|--------|----------------------------------------|------------------------|------------------------|
| **ATCM / BTCM** | **経由しない** | 該当なし（A55 に TCM はない）| **不可**（そもそもキャッシュを経由しない経路）|
| **SYSRAM** | 経由する（MPU/MMU 属性次第）| **可**（L1＋L3）| **可**（L1 のみ）|
| **LPDDR4 (DDR)** | 経由する | **可**（L1＋L3、クラスタ内コヒーレント）| **可**（L1 のみ、コア間コヒーレンシなし）|
| **xSPI（メモリマッピング領域）** | 経由する（属性次第）| 可 | 可 |

**TCM がキャッシュを経由しない理由（★ Arm 公式ドキュメントで確認済み）:**
`arm/cortex_r52_programmers_guide.pdf`（Cortex-R52 and Cortex-R52+ Programmer's Guide、Chapter 5）に、Cortex-R52 の TCM（ATCM/BTCM/CTCM）について次の記載がある:

> "TCM is always accessed as Non-cacheable Non-shareable Normal memory, and **ignores the memory attribute of the TCM memory region in the MPU**."
> （TCM は常に Non-cacheable・Non-shareable な Normal memory としてアクセスされ、**MPU 上の TCM 領域に設定されたメモリ属性を無視する**）

さらに「TCM はオーバーラップした他のメモリ領域より優先度が高い」とも明記されている。これが TCM の「常に一定レイテンシ」という特性の正体——**キャッシュヒット/ミスという概念自体が TCM には存在しない**。裏を返せば「TCM をキャッシュに乗せてさらに速くする」ことはできないし、その必要もない（TCM 自体が既に最速の階層）。以前の版では「Arm 一般知識、Renesas マニュアルに明記なし」とだけ記していたが、Arm 公式資料の直接引用として確認できたため訂正する。設定方法の詳細は [12_ddr_noncacheable_region_setup.md](12_ddr_noncacheable_region_setup.md) §1.6 を参照。

**SYSRAM がキャッシュ可能であることの根拠（マニュアル明記）:**
「13.5.5 排他的アクセスの制限事項」および「44.5.4 排他的アクセス」に、**「システム SRAM が CPU の MPU または MMU の設定でキャッシャブルかつ非共有に設定されている場合」**という条件が明記されている。これは SYSRAM が（TCM と異なり）**キャッシュ可能な通常のバス経由メモリ**として扱われていることの裏付け。ウォームな状態を維持できれば、A55（L1+L3）でも R52（L1）でも SYSRAM への実アクセス頻度を減らして体感速度を上げられる。

**DDR 上のコア間コヒーレンシに関する注意（[10] Phase3.2 の理由の補足、★ Arm 公式ドキュメントで確認済み）:**
`arm/cortex_r52_programmers_guide.pdf` Chapter 5 に「Cortex-R52/R52+ processors do not implement the cache coherency logic between the cores in a cluster.」（クラスタ内のコア間でキャッシュコヒーレンシロジックを実装していない）と明記されている。したがって R52 CPU0 と CPU1 がそれぞれ DDR 上の同じ領域をキャッシュした場合、一方の書き込みがもう一方のキャッシュに自動反映される保証はない。共有領域は非キャッシュ属性にするか、明示的なキャッシュクリーン／インバリデートを行うこと（A55 クラスタ内の 4 コア同士は ACE でコヒーレントだが、R52 側や A55⇔R52 間は対象外）。

同資料には追加で 2 点の実装上の特性が明記されている:
- **「Shareable 属性が付いたデータはキャッシュしない」**（"do not cache data that is marked as sharable"）— R52 側では共有 IPC 領域を Shareable にマークするだけでも、R52 はキャッシュしなくなる（Non-cacheable な AttrIndx を明示しなくても同等の効果）。ただし **これは R52 固有の挙動で、A55（Armv8-A）は Shareable な Normal memory を通常どおりキャッシュする**（ハードウェアスヌープでコヒーレンシを取る設計のため）。R52⇔A55 間の共有では、A55 側は別途 Non-cacheable 化またはキャッシュメンテナンスが必要（詳細: [12] §1.7）。
- **「D キャッシュの書き込み動作は、リージョン属性が Write-Back でも常に Write-Through」**（"The write behavior for the data cache is always write-through"）— R52 の書き込みは比較的速やかに実メモリへ反映されるが、読む側が古いキャッシュ内容を返すリスクは別途対策が必要な点に変わりはない。

**xSPI（フラッシュのメモリマッピング領域）については:**
- xSPI コントローラ自体に**プリフェッチバッファ**（37 章）があるため、連続読み出しは CPU キャッシュなしでも比較的高速。
- フラッシュ内容を実行中に書き換える運用（ファームウェア更新等）がある場合、**CPU 側キャッシュと xSPI コントローラ側プリフェッチバッファの両方**を無効化する必要がある点に注意（本マニュアルに XiP 時のキャッシュ運用の具体的注意事項の記載は見当たらず、一般的な XiP 設計上の注意点として付記）。
- 本ロードマップ（[10]）は基本的に xSPI から読み出した後 TCM/SYSRAM/DDR にコピーしてから実行する設計なので、xSPI 自体をキャッシャブルにする必要性は薄い。

### 5.4 ★確定仕様: Cortex-A55 は AArch32 で使用する — ここまでの速度予測は変わるか

出典: `arm/cortex_a55_trm_r2p0.pdf` Table A1-1（実装オプション一覧）、Table A1-2（準拠仕様）、Table A5-2（AArch32/AArch64 の挙動差異）。詳細な設定方法は [12_ddr_noncacheable_region_setup.md](12_ddr_noncacheable_region_setup.md) §2 参照。

まず前提の確認: RZ/N2H マニュアル表2.1（p.176）は A55 の命令セットを「Armv8.2-A A64命令セット (AArch64)」と記載しているが、Arm 公式 TRM の実装オプション一覧に「AArch32 サポートの有無」という構成オプション自体が存在せず、Table A1-2 に「AArch64 and AArch32 execution states at all Exception levels」（全 Exception Level で両方の実行状態に対応）と明記されているため、**この A55 実装で AArch32 は常に利用可能**。RZ/N2H マニュアルの記載は要約であり矛盾ではない。

**結論: ここまでの速度予測（§1〜§5.3）は AArch32 でも基本的に変わらない。** 理由は、L1/L3 キャッシュのヒット/ミスレイテンシ、SYSRAM の 250 MHz ドメインでの物理レイテンシ、DDR のコントローラ/調停オーバーヘッドは、いずれも**メモリシステムのハードウェア特性**であり、CPU が AArch32 命令（A32/T32）を実行しているか AArch64 命令（A64）を実行しているかとは**独立**しているため。NEON/浮動小数点命令も A32/T32 の両方でサポートされており、演算能力自体が実行状態で制限されるわけでもない。

ただし、以下は AArch32 特有の**副次的な**差異として押さえておくべき点（TRM Table A5-2「AArch32 and AArch64 behavior differences」より）:

| 項目 | AArch32 | AArch64 |
|------|---------|---------|
| 変換テーブル形式 | Armv7 + LPAE 相当（[12] §2.2）| Long-descriptor 形式の拡張 |
| **変換テーブルの粒度 (translation granule)** | **4KB 固定**（VMSA・LPAE とも）| 4KB／16KB／64KB から選択可 |
| ASID サイズ | **8 bit 固定** | 8 または 16 bit（`TCR_ELx.AS` 依存）|
| VMID サイズ | 8 bit 固定 | 8 または 16 bit |
| 物理アドレスサイズ | 40 bit（LPAE 使用時、コアの実装上限まで）| 最大 40 bit（同上限）|

- **物理アドレスサイズは実質同じ**（どちらも A55 の実装上限 40 bit まで到達可能、LPAE 使用時）。DDR の到達可能範囲に差は無い。
- **翻訳粒度が 4KB 固定**である点は、AArch64 なら選べる 16KB/64KB 粒度が使えないことを意味するが、4KB 粒度のままでも上位レベルのブロック記述子（2MB/1GB 相当）は利用可能なため、**実際の TLB ミス率への影響は限定的と考えられる**（大きな差は生じにくい）。ただし NORTi のメモリマップ設計（ページ数・TLB プレッシャー）によっては多少の差が出得るため、断定はしない。
- **ASID が 8 bit 固定**（AArch64 なら 16 bit を選べる場合がある）は、同時に区別できるアドレス空間（プロセス/タスクコンテキスト）の数が少なくなることを意味する。TLB フラッシュ頻度に影響しうるが、これは OS 設計（NORTi のタスク数・ASID 割り当て方針）の話であり、単発のメモリアクセスレイテンシには影響しない。
- **R52 はそもそも Armv8-R AArch32 専用コア**なので、A55 も AArch32 になったことで、**両コアの実行状態が揃う**（命令セットが両方とも 32 bit 系になる）。これはコード資産の共通化やツールチェーン統一の観点でプラスに働く可能性がある一方、[11] 全体の速度比較の結論そのものには影響しない。

## 6. まとめ

| 質問 | 回答 |
|------|------|
| 命令フェッチ速度に違いは出るか | **出る。** ただし「ワーキングセットが最速階層に収まり常駐できるか」次第で効き方が変わる。溢れる／不規則アクセスの場合: TCM(≈2ns, 決定的) < SYSRAM(RAM内部で8-12ns + バス調停・クロック跨ぎが上乗せ) ≪ LPDDR4(数十ns + コントローラ/調停オーバーヘッド + 167msごと1.6µsの完全アクセス不可期間) の順で悪化。収まって常駐できる場合はコア自体の性能（クロック・IPC）が支配的になる |
| R52+TCM と A55+SYSRAM／A55+キャッシュ、どちらが速いか | **メモリアクセスが絡む・決定性が要る処理は R52+TCM が優位**（専有・直結・無調停で常に一定）。**メモリアクセスがほぼ発生しない純計算処理は A55（高クロック・高性能コア、キャッシュがウォームなら）の方が速くなり得る。** 単純にどちらかが常に勝つわけではなく処理内容依存 |
| SYSRAM 同士（R52 vs A55）なら | **A55 の方が速い可能性が高いという推測**（SYSRAM 自体の物理レイテンシは同一だが、A55 は高クロック・大きいキャッシュでレイテンシを隠しやすい）。ただし本マニュアルに実測比較データはなく、一般的なアーキテクチャ知識からの推論である点に注意 |
| A55 単体で最速の選択肢は | ウォームな **L1/L3 キャッシュヒット**（ただし非決定的）。決定性が要るなら SYSRAM が現実的な上限 |
| 全部を DDR にする必要はあるか | **ない。** 速度・決定性が必要な処理は R52→TCM、A55→SYSRAM に残し、それ以外（本体コード・大容量データ）を DDR に置く混在構成が可能 |
| TCM はキャッシュされるか | **されない（経由しない）。** Arm 公式 Cortex-R52 Programmer's Guide に「TCM は常に Non-cacheable・Non-shareable として扱われ、MPU のメモリ属性設定を無視する」と明記されている。だからこそ常に一定レイテンシになる |
| SYSRAM・DDR はキャッシュされるか | **される（MPU/MMU 属性次第）。** A55 は L1+L3、R52 は L1 でキャッシュ可能。ただし R52 CPU0/CPU1 間・A55⇔R52 間にハードウェアコヒーレンシはないので共有領域の扱いに注意 |
| A55 を AArch32 で使うと速度予測は変わるか | **基本的に変わらない。** キャッシュ/SYSRAM/DDR のレイテンシはハードウェア特性であり実行状態（AArch32/AArch64）に依存しない。翻訳粒度が 4KB 固定・ASID が 8bit 固定という副次的な差はあるが、単発アクセスのレイテンシへの影響は小さい（詳細 §5.4）|

# デバッグインタフェース（マニュアル 10 章）

出典: ユーザーズマニュアル ハードウェア編 R01UH1039JJ0130 Rev.1.30、「10. デバッグインタフェース」p.292-301、
関連: 「4. 動作モード」p.187-216、「45. OTP」p.2944-2953、「17.7.6 各ブートモードの端子割り当て」p.769-770、
ハードウェアデザインガイド R01AN7419JJ0120 Rev.1.20「1.2.3 リセット回路」「2. 動作モード」「14. 未使用端子」。

## 10.1 全体像

- Cortex-A55 クワッド ＋ Cortex-R52 ×2 を **Arm CoreSight** で統合。
- デバッグ用 **JTAG / SWD**、トレース用 **ETR**（メインバス A へ出力）。
- トレース FIFO: ETF_A55 16 KB、ETF_R52 16 KB、ETF_C（最終ファネル）8 KB。
- **DAP → APB-AP (AP=1) / APB-AP (AP=0) / AXI-AP (AP=2)** の 3 AP。
  - AP=0: OCD 認証レジスタ（OIRn / OSR）へアクセスする専用 AP。
  - AP=1: CoreSight / 各コアのデバッグ APB（下記アドレスマップ）。
  - AP=2: AXI 経由でメインバスへ直接アクセス。

## 10.1 TAP セレクトと BSCANP（重要：接続可否に直結）

- 本 LSI には **バウンダリスキャン用 TAP** と **CoreSight デバッグ用 TAP** があり、`BSCANP` 端子の入力レベルで選択。
- **CoreSight デバッグを使う場合は `BSCANP` = Low 必須。** `BSCANP` = High はバウンダリスキャンモードになり、JTAG デバッガ（PALMiCE4 等）は CoreSight に到達できない。
- `BSCANP` は専用端子（GPIO 兼用ではない）。VDD33 ドメイン。
  - 576 ピン FCBGA: ボール **AA6**（VDD33）
  - 669 ピン FCBGA: ボール **AA6**（VDD33）
- 未使用端子処理表では「バウンダリスキャンイネーブル端子として使用」＝明示的にレベルを与える端子。デバッグするなら Low 固定。

## 10.3.8 デバッグ端子（表 10.8）

| 名称 | 端子 | 兼用 GPIO | I/O | 備考 |
|------|------|-----------|-----|------|
| TCK | TCK | P08_3 | 入力 | SWD 時は SWCLK。初期機能 = TCK |
| TMS | TMS | P08_1 | 入出力 | SWD 時は SWDIO。初期機能 = TMS |
| TDI | TDI | P08_2 | 入力 | 初期機能 = TDI |
| TDO | TDO | P08_4 | 出力 | 初期機能 = TDO |
| TRST# | TRST# | （専用） | 入力 | TCK 非同期。Low で TAP リセット。`TRST# = Low かつ RES# = Low` で TAP＋デバッグ回路がリセット |
| BSCANP | BSCANP | （専用） | 入力 | High=バウンダリスキャン有効、**Low=CoreSight デバッグ** |

- **LSI 初期状態はデバッグインタフェース = JTAG モード。** SWD を使う場合はデバッガから SWD へ切替が必要（TDI/TDO は GPIO 転用可）。
- RZ/N2H 576 ピン FCBGA のボール（マニュアル表 1.21）:
  - `TRST#` = **V7**(VDD33)、`RES#` = **AC4**(VDD33)、`BSCANP` = **AA6**(VDD33)、`MDX` = **AC1**(VDD33)
  - `TCK` = **AC5**(P08_3, VDD33)、`TMS` = **AD3**(P08_1, VDD33)、`TDI` = **AD4**(P08_2, VDD33)、`TDO` = **AC3**(P08_4, VDD33)
  - `MDD` = **AD7**（P06_6、VDD1833_4 = xSPI0 ドメイン、**XSPI0_RESET0# と兼用**）

## 10.3.1 / 10.3.2 接続例

JTAG: TCK / TMS / TDO / TDI / TRST# の 5 本 ＋ エミュレータの nSRST を RES# へ。
SWD: SWCLK(TCK) / SWDIO(TMS) の 2 本 ＋ nSRST→RES#、nTRST→TRST#。TDI/TDO は GPIO 転用可。

```
エミュレータ        リセット回路          RZ/T2H・RZ/N2H
  nSRST  ─────────────────────────▶ RES#
  nTRST  ────────────────────────▶ TRST#
  TCK    ────────────────────────▶ TCK
  TMS    ◀───────────────────────▶ TMS
  TDI    ────────────────────────▶ TDI
  TDO    ◀────────────────────────  TDO
```

## 10.3.3 リセット設定とエミュレータ接続手順（★接続シーケンスの肝）

ボード設計要件:
- **電源投入時、RES# がアサートされている間は TRST# を Low にすること。**
- **TRST# 単独で制御できるボード構成にすること。**
- エミュレータ未接続時は、TRST# を Low 固定するか、RES# と同じ信号を TRST# に入れる。
- CoreSight デバッグ時は **BSCANP = Low**。

接続シーケンス（マニュアル本文）:
1. `RES# = Low` かつ `TRST# = Low` → CPU とデバッグ部がリセット状態。
2. `RES#` を Low に保ったまま `TRST#` を High → **SWJ-DP レジスタ設定用の TAP アクセスが可能**。
3. `RES#` を High にする → **AP=0 で OCD レジスタ（OIRn / OSR）へアクセス可能**。
4. **JTAG 認証に合格 or 認証不要** の場合、**内蔵ブートコードの実行後**にデバッグ設定が可能。
   - タイミング図（図 10.4 / 10.5）では「PLL 安定待ち **500 µs**」→「ブートコード実行の完了」→「JTAG が CPU 動作を設定（デバッグ許可）」。

エミュレータの nTRST 駆動能力による違い:
- **nTRST を High 駆動できないエミュレータ**（図 10.4）: TRST# を外部プルアップし、エミュレータが Low アサート。リセット IC は**オープンドレイン型**。
- **nTRST を High 駆動できるエミュレータ**（図 10.5）: TRST#（High/Low とも）をエミュレータが制御。

## 10.2 OCD 認証レジスタ（デバッガビュー AP=0）

### OIRn : OCD 認証 ID コードレジスタ n (n = 0〜3)
- Address: `0x0008_0000 + 0x04 × n`（AP=0）
- `IDn[31:0]` = W。n=0→ID[31:0]、n=1→[63:32]、n=2→[95:64]、n=3→[127:96]（128 bit 認証 ID）。
- **4 本すべてに一度書くと、以降の書き込みは全ブロック。**

### OSR : OCD ステータスレジスタ
- Address: `0x0008_0010`（AP=0）
- `RESULT[1:0]` (R): 認証結果
  - `00b`: 未認証
  - `01b`: 認証レベル1 パス（R52: EL2/EL1/EL0、A55: EL3/EL2/EL1/EL0 のアクセス許可）
  - `10b`: 認証レベル2 パス（R52: EL1/EL0、A55: EL2/EL1/EL0 のみ許可）
  - `11b`: 認証失敗、またはアクセス永久禁止
- `WFLG` (R): 全 OIRn 書き込み済みフラグ
- **認証なし選択時は RESULT = `01b`（＝フルアクセス許可）を示す。**

## 10.3.7 デバッグ認証（セキュリティ機構）

- 認証レベルは **OTP の `AUTHMODEJ` 領域**（OTP アドレス `0x0E9`, MODE[8:0]）で決定。
  - 有効ビットは 3bit ずつの OR: `B2=OR(MODE[8:6])`, `B1=OR(MODE[5:3])`, `B0=OR(MODE[2:0])`
  - `B2 B1 B0` = `000`: **認証なし**
  - `= 001`: 認証レベル1（EL2 と EL1/EL0）
  - `= 01x`: 認証レベル2（EL1/EL0 のみ）
  - `= 1xx`: **JTAG 接続を永久に禁止**
- 認証レベル1/2 の場合、デバッガから OIRn に 128 bit ID を書き、OTP 事前格納 ID（`JID1P` = 0x0EB〜0x0EE / `JID2P` = 0x0EF〜0x0F2）と比較。全 OIRn 書き込みで認証開始、結果は OSR。
- 認証失敗 → **一切のデバッグ接続不可**。リトライには **リセット（RES# / システムソフトウェアリセット / エラーリセット）** が必要。
- 非セキュリティ対応製品は平文比較。**セキュリティ対応製品（M48GBG）はハッシュ認証**（`MDD` 端子でハッシュ JTAG 認証を有効化、[04_boot_modes.md](04_boot_modes.md) 参照）。
- 未書き込みの OTP は全ビット 0 = `AUTHMODEJ = 0x000` = **「認証なし」** → 出荷まっさらな石ならデバッグは許可されるはず。

### 図 10.6 デバッグ認証手順（平文）
```
テストロジックリセット
      │
 OSR[1:0] をチェック
   ├ 00b (AUTHMODEJ=001b/01xb) → 認証待機 → AP0 の OIRn に書き込み → デバッグ認証
   │        ├ 成功 → OSR[1:0]=01b/10b → APB-AP1 CSW.DeviceEn=1 まで待機 → デバッグレジスタにアクセス可能
   │        └ 失敗 → OSR[1:0]=11b → 接続禁止 → デバッグ I/F アクセス失敗
   ├ 01b (AUTHMODEJ=000b) → 認証なし → （そのままデバッグ可）
   └ 11b (AUTHMODEJ=1xxb) → 接続禁止 → デバッグ I/F アクセス失敗
```

## 10.4 使用上の注意事項

- **10.4.1 メインバスへのアクセス**: DAP からメインバスへは R52 CPU0/CPU1・A55・AXI-AP のいずれか経由。
  セカンドブート CPU（R52 CPU0 または A55 Core0）以外の CPU 経由の場合、事前に該当 CPU のソフトウェアリセット解除＋モジュールストップ解除が必要。AXI-AP 経由なら AXI-AP 用 M-MPU を内部リソースアクセス可に変更が必要。
- **10.4.2 認証レベル**: レベル2 は CPU が EL1/EL0(R52) または EL2/EL1/EL0(A55) のときのみ有効。EL2(R52)/EL3(A55) のみアクセス可能なデバッガではレベル2 を使わない。
- **10.4.3 デバッグリセット**: **ブート動作中はデバッガからのリセット要求が禁止。**

## ハードウェアデザインガイド側の該当記述

- **1.2.3 リセット回路**: `SLG7RN46360V` 等でリセットタイミングを生成。`RSTdly#` は 1 µs(typ) 遅延。RES#/TRST#/RSTOUT0#/RSTOUT1# を管理。
- **2.4 注意事項**: モード端子 MDn/MDV/MDD/MDWn は Ethernet 端子と兼用。プルアップ／プルダウン抵抗は LSI から **1.5 cm 以内**に配置。
- **14. 未使用端子**: `TRST#`→プルダウン or RES# 同信号、`TCK`→プルダウン、`TMS/TDI`→VDD33 プルアップ、`TDO`→オープン、`MDX`→**常時 VSS プルダウン**、`BSCANP`→プルダウン（デバッグ時）。

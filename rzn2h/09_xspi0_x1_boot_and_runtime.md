# xSPI0 x1 ブートモード 詳細（ブート時 + ランタイム）

[← README（目次）へ戻る](README.md)

対象: R9A09G087M48GBG、動作モード = **xSPI0 ブートモード（x1 ブートシリアルフラッシュ）**（MD2:0 = `000b`）。
出典: マニュアル「4.6.4 xSPIブートモード」p.195-198、「37. 拡張シリアルペリフェラルインタフェース (xSPI)」p.2747-2805、
「17.7.6.1 xSPIブートモードの端子割り当て」p.770。

このモードでは **Cortex-R52 CPU0 が唯一のブート実行 CPU**（ブート ROM は常に R52 CPU0 で走る）。
[10_amp_multicore_bringup_roadmap.md](10_amp_multicore_bringup_roadmap.md) の Phase 0 の前提資料。

## 1. ブート時の動作（ブート ROM）

### 1.1 使用端子・電気仕様

| 項目 | 内容 |
|------|------|
| 使用端子 | `XSPI0_CKP`、`XSPI0_CS0#`、`XSPI0_IO0`、`XSPI0_IO1` |
| I/O ドメイン | `VDD1833_4`（`MDV` 端子で 1.8 V / 3.3 V を選択、ブート ROM が I/O バッファ駆動能力最適化に使用）|
| プロトコル | **1S-1S-1S 固定**（データ信号数によらず）|
| 内部アドレス空間 | xSPI0 = `0x4000_0000`〜`0x4FFF_FFFF`（CS0 + CS1 合計で最大 256 MB）|

### 1.2 ブート ROM の初期設定値（ローダ用パラメータ転送まで）

| 項目 | 値 |
|------|-----|
| CPU クロック (CPU0CLK) | 500 MHz |
| xSPI ビットレート (XSPI_CLK0) | **12.5 MHz**（既定。ローダ用パラメータの `ACCESS_SPEED` で変更可）|
| コマンド | 読み出し `0x03`、1 バイト出力 |
| アドレス出力 | 3 バイト |
| ダミーサイクル | 0 |
| データ幅 | 1 bit |
| 駆動／サンプリングエッジ | `XSPI0_CKP` の立下り |
| フラッシュリセット | ソフトウェア（`0x66` + `0x99`）※ x1 はハードウェアリセット端子なし |

### 1.3 ブート処理フロー（4.6.1 / 4.6.4.1 の要約）

1. `XSPI0_CKP`/`CS0#`/`IO0`/`IO1` を上記初期値で有効化。
2. 外部メモリからローダ用パラメータ（xSPI0 空間の `0x4000_004C` 以降）を読み出し、`CHECK_SUM` を検証。
3. ローダ用パラメータの `ACCESS_SPEED`／`WRAPCFG_V`／`COMCFG_V`／`LIOCFGCS0_V` で xSPI0 を高速化設定。
4. `LDR_ADDR_NML` から `LDR_SIZE_NML` バイトのローダプログラムを読み出し、`DEST_ADDR_NML` へ展開。
5. `BOOTCPU_FLG = 0`（今回の想定）なら **R52 CPU0 がそのままローダプログラムへ分岐**。

### 1.4 ローダプログラムの配置制約（★重要：Phase 0 の設計に直結）

| 項目 | 制約 |
|------|------|
| `LDR_ADDR_NML`（xSPI0 内の格納アドレス）| `0x4000_004C`〜`0x40FF_FE00` |
| `LDR_SIZE_NML`（サイズ）| **512 バイトの倍数、最大 52 KB**（R52 CPU0 ブートの場合）|
| `DEST_ADDR_NML`（展開先）| **BTCM 内 `0x0010_2000`〜`0x0010_EFFF`**（4 バイトアライン。Thumb なら bit0=1）|

- BTCM 全体は `0x0010_0000`〜`0x0010_FFFF`（64 KB）だが、展開先として使えるのは中央の約 52 KB（`0x0010_2000`〜`0x0010_EFFF`）のみ。
  先頭 8 KB（`0x0010_0000`〜`0x0010_1FFF`）と末尾 4 KB（`0x0010_F000`〜`0x0010_FFFF`）はブート ROM 自身のベクタ／作業領域として予約されていると考えられる（明記はないが、許容範囲の外側）。
- **つまり x1 ブートで直接展開できる「一段目ローダ」は最大 52 KB。** NORTi 本体＋アプリを含む本格的な R52 CPU0 イメージをここに収めるのは現実的でない。
  → [10_amp_multicore_bringup_roadmap.md](10_amp_multicore_bringup_roadmap.md) の Phase 0/0.5 で「一段目ローダ（BTCM, ≤52 KB）が xSPI0 を自前で読み直し、二段目（本体, ATCM 512 KB or SYSRAM 2 MB）をコピーしてジャンプする」という 2 段構成を提案している。

### 1.5 ブート終了時のレジスタ状態（`RESTORE_FLG` に依存、表 4.10 抜粋）

`RESTORE_FLG`（ローダ用パラメータ offset `0x10`）を `0x2236_0679` にすると、ブート終了後に xSPI0 の各種設定は**初期値へ戻る**。それ以外の値なら、**ブートで使った高速化設定がそのまま保持される**。

| レジスタ | `RESTORE_FLG = 0x22360679`（初期化される）| `RESTORE_FLG ≠ 0x22360679`（保持される）|
|----------|------|------|
| `WRAPCFG` | `0x00000000` | `WRAPCFG_V` の設定値（フラグビット無効なら初期値）|
| `COMCFG` | `0x00000000` | `COMCFG_V` の設定値 |
| `BMCFG` | `0x00000000` | `BMCFG_V` の `PREEN` のみ |
| `CMCFG0CS0` | `0x00000008` | `0x00000008`（x1 は同じ）|
| `CMCFG1CS0` | `0x00000300` | `0x00000300`（x1 は同じ）|
| `LIOCFGCS0` | 上位 16bit `0x0000` | `LIOCFGCS0_V`（フラグ次第）|
| `BMCTL0` | `0x00000001` | `0x00000001` |
| `CS0ENDAD` | ベース(`0x4000_0000`) + `CS0_SIZE` | 同左 |
| `SCKCR` | `0x00730606`（初期値）| `ACCESS_SPEED` の設定値（xSPI0: bit6, bit[2:0]）|
| `MSTPCRA` | `0x0FFF1F21` | 同左 |

**実装上の含意**: 一段目ローダで「本体イメージをもっと速く読みたい」場合は、`RESTORE_FLG ≠ 0x2236_0679` にして高速化状態を維持するか、一段目ローダ自身が §2 の手順で xSPI0 を再設定する。

## 2. ランタイムでの xSPI0 操作（一段目/二段目ローダ、および運用中のフラッシュアクセス）

ブート完了後は xSPI0 は**通常の周辺モジュール**として CPU から自由に再設定・使用できる（書き込み保護なし。表 37.4 の「書き込み保護」列はすべて `—`）。

### 2.0 ★ 3 行まとめ（読み出し／書き込み／直接実行の使い分け）

| 操作 | できるか | 方法 |
|------|---------|------|
| **フラッシュ読み出し → RAM（TCM/SYSRAM/DDR）へのロード** | **できる** | メモリマッピングモードへの単純な逐次読み出し（**memcpy 相当**）で足りる。専用ドライバ不要（§2.3）|
| **フラッシュへの書き込み（プログラム／イレース）** | **メモリマッピングでは不可**、別途実装すれば可 | **マニュアルコマンドモード**で `WREN → Program/Erase → ステータスポーリング` という SPI コマンドのやり取りを明示的に実装する必要がある（§2.5, §2.6）|
| **フラッシュ上のコードを直接実行（XiP、RAM へロードせず命令フェッチ）** | **技術的には可能**だが**実用上は非推奨** | メモリマッピングモードで直接分岐すれば実行できるが、RAM より 1〜2 桁遅い。R52 のリアルタイム処理には不適、通常は使わない（§2.4）|

以下、各項目の詳細。

| モード | 用途 | 主要レジスタ |
|--------|------|-------------|
| **メモリマッピングモード**（XiP 的動作）| `0x4000_0000`〜 への AXI アクセスを自動的に xSPI トランザクションへ変換。**単純な連続読み出し（フラッシュ→DDR/SYSRAM へのコピーや直接実行）はこれで足りる** | `CMCFG0/1/2CS0`（アドレスサイズ、`RDCMD`、`RDLATE`）、`LIOCFGCS0.PRTMD`（プロトコル）、`CMCFG0CS0.FFMT`（フレームフォーマット）、`WRAPCFG`（駆動/サンプリングタイミング）|
| **マニュアルコマンドモード** | イレース／プログラム／ステータスポーリングなど、メモリマップ読み出しでは表現できない任意コマンド（最大 4 コマンドを連結可）| `CDCTL0`〜`CDCTL2`、`CDTBUFn`／`CDABUFn`／`CDD0BUFn`／`CDD1BUFn`（n=0〜3）|

### 2.2 設定変更フロー（37.4.7.1〜37.4.7.3）

1. **電圧・アドレス空間設定**: `IOVOLCTL.XSPI_MDV`、`CS0ENDAD`、`CS1STRAD`、`CS1ENDAD`
2. **プロトコルモード設定**: `LIOCFGCSn.PRTMD`（1S-1S-1S / 4S-4D-4D / 8D-8D-8D 等）
3. **フレームフォーマット設定**: `CMCFG0CSn.FFMT`
4. **駆動／サンプリングタイミング設定**: `WRAPCFG`、`LIOCFGCSn`
5. （自動キャリブレーションを使う場合）`CCCTL0CSn.CAEN=0` を確認 → `CCCTL1-7CSn` でコマンド設定 → `CCCTL0CSn`（`CANOWR`/`CAITV`/`CASFTSTA`/`CASFTEND`）→ `CAEN=1`

**設定変更前に必ず通信を完全停止**すること（37.4.7.2）:
- `CCCTL0CSn.CAEN = 0`（自動キャリブレーション無効を確認）
- `CDCTL0.TRREQ = 0`（保留中マニュアルコマンドなしを確認）
- xSPI0 全体をリセット/ストップする場合は 13.4.3 のスレーブストップ手順（`SSTPCR6.XSPI0_REQ`→`ACK` ポーリング、対応する `MRCTLA.[4]` / `MSTPCRA.[4]`）に従う。

### 2.3 メモリマッピング読み出しの仕組み（37.4.3）

- AXI アクセスのアドレス・データはそのまま xSPI トランザクションへ渡され、コマンド／サイズ／レイテンシは `CMCFG0/1/2CSn` の設定値から供給される。
- 読み出し用: `CMCFG1CSn.RDCMD[15:8 or 15:0]`（コマンド）、`CMCFG0CSn.ADDSIZE`（アドレスサイズ）、`CMCFG1CSn.RDLATE`（レイテンシサイクル）。
- 書き込み用: `CMCFG2CSn.WRCMD`、`WRLATE`。**NOR フラッシュへの書き込み（プログラム/イレース）には使えない（§2.5 で詳述）。**
- バースト転送は AXI の `AWBURST`（INCR/WRAP）に応じて xSPI フレームに変換される（図 37.12）。プリフェッチバッファにより連続読み出しは高スループット。

### 2.4 ★ XiP 実行（メモリマッピングモードでの直接命令フェッチ）は可能か

**結論: 可能。** メモリマッピングモードは AXI アクセスを自動的に xSPI トランザクションへ変換する仕組みなので、CPU の命令フェッチも「AXI 読み出しアクセスの一種」として扱われ、**`0x4000_0000`〜のアドレスに直接分岐・実行すれば、RAM へコピーせずそのまま命令フェッチできる**。これがいわゆる XiP（eXecute In Place）で、xSPI の仕様表（37.1）にも「XiP モードに対応」と明記されている。

**ハードウェアは連続アクセス（＝ストレートラインの命令フェッチと相性が良い）を高速化する仕組みを持つ:**
- **プリフェッチバッファ**（37.4.3）: インクリメントアドレスで近接した読み出しが続く場合、内部バッファがヒットしてバス上の新規トランザクションを省略できる。
- **XiP モード**（37.4.3.6, `CMCTL.XIPEN`/`XIPENCODE`/`XIPEXCODE`）: 対応するスレーブデバイスに対し、**2 回目以降の連続読み出しでコマンドバイトの送信自体を省略**できる（レイテンシフィールドに専用コードを挿入するだけで前回コマンドが暗黙的に繰り返される）。ただし**メモリマッピングモードでのみ有効**、かつ**読み出し／書き込みを混在させると使えない**（一方向アクセス専用）という制約がある。

**それでも RAM に比べて桁違いに遅い点は変わらない:**
- xSPI の仕様上の最大 RAW スループットは **266 MB/s**（37.1 概要）。この理論最大値でも、32 バイトのキャッシュライン 1 本を埋めるのに ≈120 ns かかる計算になり、SYSRAM（≈12 ns）の約 10 倍、TCM（≈2 ns）の約 60 倍遅い（コマンド・アドレス・レイテンシのオーバーヘッドを含めればさらに悪化）。
- ブート直後の既定クロック（**12.5 MHz、1S-1S-1S**、[04_boot_modes.md](04_boot_modes.md)）のままなら、キャッシュライン 1 本の転送だけで**数 µs 単位**かかる。
- プリフェッチ／XiP モードは「連続増加アドレス」でしか効かないため、**分岐でキャッシュに無い新しい領域へ飛ぶたびに、フルのコマンド＋アドレス＋レイテンシ＋データ転送コストを払う**（[11_memory_performance_comparison.md](11_memory_performance_comparison.md) の「ワーキングセットが収まらない場合」に相当する、最も遅いケース）。

**実例による裏付け**: RZ/N2H のブート ROM 自身も、xSPI0 から読み出したローダプログラムを **XiP 実行せず、必ず BTCM/SYSRAM へ展開してから実行する**（§1.3/1.4）。クリティカルな初期ブートコードでさえ Renesas 自身が XiP を採用していないことは、直接実行が性能面で推奨されないことの実例的な裏付けと言える。

**実用上の指針:**
- **R52 のリアルタイム制御ループには不適**。分岐先が flash 領域だった場合の予測不能な遅延（µs 単位）は、TCM を使う目的（決定性）と真っ向から矛盾する。
- 使うとすれば、**大きいが滅多に実行されない読み出し専用コード**（A55 側の非クリティカルなアプリケーションロジック、エラーハンドラ、文字列/テーブルデータ等）で、RAM 容量の節約を優先したい場合。その場合は当該領域を **MPU/MMU でキャッシャブル（Normal, Write-Back）に設定**し（[12_ddr_noncacheable_region_setup.md](12_ddr_noncacheable_region_setup.md) 参照）、初回実行の遅さを許容しつつ、以降のホットループ実行は CPU 自身の L1/L3 キャッシュに載せて高速化する、という使い方になる。
- 本ロードマップ（[10]）は全コアの本体コードを TCM/SYSRAM/DDR へコピーしてから実行する設計であり、上記の理由から**これが正しい選択**。XiP は将来 RAM 容量が逼迫した場合の追加選択肢として位置づけられる。

### 2.5 ★ 書き込み側: メモリマッピングされたアドレスへの書き込みで NOR フラッシュへプログラムできるか

**結論: できない。** メモリマッピングモードの書き込みパス（`CMCFG2CSn.WRCMD`/`WRLATE`、37.4.3.2）は「1 回の AXI 書き込み → 1 回の固定コマンドを伴う xSPI 書き込みトランザクション」という単純な対応関係しかない。これは **OctaRAM/HyperRAM のような RAM 系デバイス**（イレース不要・任意アドレスへ即座に上書き可能。37 章機能一覧の「書き込みデータマスクに対応」も部分バイト書き込みという RAM 的な機能）には適合するが、**NOR フラッシュのプログラム／イレース手順とは構造的に噛み合わない**（以下はマニュアルの直接記載ではなく、一般的な NOR フラッシュデバイスの動作仕様との整合性から導かれる結論）:

1. **Write Enable (WREN) コマンドの前置が必要**: 大半の NOR フラッシュは Program/Erase コマンドの直前に毎回 `WREN`（例: `0x06`）を送る必要があるが、メモリマッピング書き込みは 1 AXI アクセスにつき固定 1 コマンドしか発行できず、`WREN` を自動的に挿入する仕組みがない。
2. **イレースの概念が無い**: NOR フラッシュは 1→0 方向にしかビットを変更できず、0→1 に戻すには**セクタ/ブロック単位の事前イレース**が必須。メモリマッピング書き込みには「イレース」という操作自体が存在しない。
3. **完了待ち（ステータスポーリング）が必要**: Program/Erase の実行完了まで数十 µs〜数百 ms を要し、ソフトウェアはステータスレジスタの `WIP`（Write In Progress）ビットをポーリングして完了を確認してから次の操作に進む必要があるが、メモリマッピングモードにはこの待ち合わせの仕組みがない。
4. デバイスによってはページ境界（多くの NOR フラッシュで 256 バイト）を跨いだプログラムができない、といった制約もある。

→ **NOR フラッシュ（xSPI0 のブート用フラッシュを含む）への書き込み・消去は、`37.4.2 マニュアルコマンドモード`（§2.6、`CDTBUFn`/`CDABUFn`/`CDDxBUFn` を最大 4 つ連結）で `WREN → Page Program（またはセクタ/ブロックイレース）→ ステータスポーリング` という手順を明示的に実装する必要がある。** 周期モード（表 37.10）を使えば、ステータスポーリング部分は自動化できる。
なお、**xSPI に OctaRAM/HyperRAM を接続する用途**であれば、上記のイレース/WREN/ポーリングは一切不要なので、メモリマッピングモードでの単純な読み書きがそのまま使える。

### 2.6 マニュアルコマンドモード（37.4.2, 37.4.7.4）

フラッシュのステータスレジスタ読み出し、セクタ/ブロックイレース、ページプログラムなど、メモリマップ読み出しで表現できない操作に使用。`CDTBUFn`/`CDABUFn`/`CDDxBUFn`（n=0〜3）に「トランザクション種別・コマンド・コマンドサイズ・アドレス・アドレスサイズ・データ・データサイズ・レイテンシ」を設定し、`CDCTL0`〜`2` で発行を制御。**4 バッファを連結して複数コマンドを 1 シーケンスとして実行可能**（例: Write Enable → Page Program → Status Poll）。周期モード（表 37.10）を使えばステータスポーリングも自動化できる。

### 2.7 割り込み（37.4.6, 表 37.14）

| フラグ | 意味 | 信号 |
|--------|------|------|
| `CMDCMP` | マニュアルコマンド完了 | `XSPIm_INT` |
| `INICMP` | 初期化完了 | `XSPIm_INT` |
| `PATCMP` | パターン一致 | `XSPIm_INT` |
| `CASUCCS0/1` | キャリブレーション成功 | `XSPIm_INT` |
| `CAFAILCS0/1`, `BUSERR`, `INTCS0/1`, `ECSCS0/1`, `DSTOCS0/1`, `PERTO` | 各種エラー | `XSPIm_INTERR` |

ポーリングでも良いが、大量データ転送や複数コマンド連結時は `CMDCMP`/割り込みでの完了検知が実装しやすい。

## 3. R52 CPU0 一段目ローダの設計指針（まとめ）

1. ブート ROM が展開した一段目ローダ（BTCM、最大 52 KB）は、**最低限**: クロック概略設定・xSPI0 の高速化（必要なら §2.2 で再設定）・二段目イメージの位置とサイズの把握、を行い、xSPI0 の**メモリマッピングモード**で二段目イメージを読み出しコピーする。
2. コピー先は当面 **ATCM（512 KB）** または **SYSRAM（2 MB、他バスマスタと共有）**。DDR はこの時点ではまだ初期化されていない（[10_amp_multicore_bringup_roadmap.md](10_amp_multicore_bringup_roadmap.md) Phase 2 で行う）。
3. 二段目（本体 NORTi + アプリ、ATCM/SYSRAM 常駐）で DDR 初期化・他コア起動・各コア用イメージの DDR へのロードを行う。三段目以降は xSPI0 のメモリマッピングモードで十分（大容量転送はプリフェッチにより高スループット）。
4. NOR フラッシュへの書き戻し（イレース/プログラム）が製品運用上必要（ファームウェア更新等）なら、マニュアルコマンドモード（§2.6）のドライバを別途用意する（§2.5 のとおりメモリマッピング書き込みでは不可）。今回のロードマップ（読み出し専用のロード処理）には必須ではない。
5. 「RAM へコピーせず xSPI0 を直接実行（XiP）できないか」という設計上の誘惑は、§2.4 のとおり**技術的には可能だが実用上は非推奨**（R52 の実時間性を損なう、SYSRAM/DDR より 1〜2 桁遅い）。将来 RAM 容量が逼迫した場合の非クリティカルコード向けの選択肢として頭の片隅に置いておく程度でよい。

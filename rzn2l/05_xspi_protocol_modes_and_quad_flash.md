# xSPI プロトコルモード（1S-1S-1S / 4S-4S-4S 等）と Quad シリアルフラッシュ接続

[← README（目次）へ戻る](README.md)

出典: ユーザーズマニュアル「36.2.1.7 LIOCFGCSn」p.2095、「36.2.1.4-6 CMCFG0/1/2CSn」p.2093-2094、
「36.2.2.8-9 CDTBUFn/CDABUFn」p.2101-2102、「36.3.1.1 対応するプロトコルモード」p.2117、
「3.5.4 xSPIブートモード」p.97-99。前提として [04_xspi_boot_and_runtime.md](04_xspi_boot_and_runtime.md)
（メモリマッピング／マニュアルコマンドの基本、書き込み制約、XiP）を先に参照してください。

対象: Quad（4本のデータ線 IO0-IO3）対応のシリアル NOR フラッシュを xSPI0 または xSPI1 に
接続する場合の、プロトコルモード選定と実装上の注意点。

## 1. 記法の意味（nX-mX-oX）

xSPI（および業界一般の JESD251／xSPIプロトコル）のモード名は、SPI フレームの3フェーズ
（コマンド－アドレス－データ）それぞれについて「使用するデータ線の本数」と「SDR/DDR」を
表しています。

```
   1  S  -  1  S  -  1  S
   │  │     │  │     │  │
   │  └ SDR/DDR       └ データフェーズの転送レート
   │     └ アドレスフェーズの転送レート
   └ コマンドフェーズのピン数（1=シングル,2=デュアル,4=クワッド,8=オクタル）
```

- **S** = SDR（Single Data Rate、クロックの片エッジのみでデータ転送）
- **D** = DDR（Double Data Rate、クロックの両エッジでデータ転送）
- 例: `1S-4S-4S` = コマンドは1本の線でSDR転送、アドレスとデータは4本の線（Quad）でSDR転送。
- 例: `4S-4D-4D` = コマンドは4本の線でSDR、アドレスとデータは4本の線でDDR転送。

## 2. RZ/N2L の xSPI がサポートするプロトコルモード（enumのみ、任意組み合わせ不可）

`LIOCFGCSn.PRTMD[9:0]` は自由なビットフィールドではなく、**以下7種類のコード値のみが
有効で、それ以外の値は「設定禁止」**とマニュアルに明記されています（36.2.1.7）。
つまり「コマンドは1本、アドレスは2本、データは4本」のような任意の組み合わせは作れません。

| プロトコルモード | `PRTMD[9:0]` | 系統 | 典型的なSPI NORフラッシュのコマンド例 |
|---|---|---|---|
| `1S-1S-1S` | `0x000` | xSPI標準（シングル） | `0x03` Read／`0x06` WREN／`0x05` RDSR／`0x02` Page Program／`0x20` Sector Erase 等、**ほぼ全てのSPI NORフラッシュが対応する基本コマンド全部** |
| `1S-2S-2S` | `0x048` | QSPI互換（デュアル） | `0xBB` Fast Read Dual I/O 相当（アドレス・データがデュアル） |
| `2S-2S-2S` | `0x049` | QSPI互換（デュアル） | フラッシュが対応していれば全フェーズデュアルのコマンド |
| **`1S-4S-4S`** | **`0x090`** | **QSPI互換（クワッド）** | **`0xEB` Fast Read Quad I/O 相当（アドレス・データがクワッド）＝ Quad フラッシュの定番の高速読み出しコマンド** |
| `4S-4S-4S` | `0x092` | QSPI互換（クワッド、QPI） | フラッシュを事前に QPI モードへ切り替えた場合の全フェーズクワッドコマンド |
| `4S-4D-4D` | `0x3B2` | xSPI標準（クワッドDDR） | フラッシュが対応していれば `0xED` Fast Read Quad I/O DTR 相当 |
| `8D-8D-8D` | `0x3FF` | xSPI標準（オクタルDDR） | HyperFlash / xSPI 8D-8D-8Dプロファイル2.0準拠デバイス用（本ドキュメントの対象外） |

**★ 注意（見落としやすい点）**: 「コマンド1本・アドレス1本・データ4本」という組み合わせ
（一般に **`1S-1S-4S`** と呼ばれ、SPI NORフラッシュの `0x6B` Fast Read **Quad Output**
コマンドに相当）は、上記7種類のリストに**含まれていません**。RZ/N2L の xSPI は
「アドレスとデータを両方クワッドにする」`1S-4S-4S`（`0xEB` Quad **I/O**）のみサポートし、
「データだけクワッドにする」`0x6B` 系のQuad Outputコマンドには**そのままでは対応しません**。
Quad フラッシュを選定・使用する際は、**`0xEB`（Fast Read Quad I/O）系のコマンドが使えること**
を確認してください（市販のQuad SPI NORフラッシュはほぼ全て `0xEB` に対応していますが、
稀に廉価品で `0x6B` のみのものもあるため要データシート確認）。

同様に、Quad **Page Program**（多くのフラッシュで `0x32` = コマンド1本・アドレス1本・
データ4本 = `1S-1S-4S`）も上記7種類に含まれないため、**xSPI経由ではそのまま発行できません**。
書き込みは §5 のとおり `1S-1S-1S` の標準 Page Program（`0x02`）で行うのが無難です。

## 3. 重要な構造上の制約：プロトコルモードは CS 単位、コマンド単位ではない

`LIOCFGCSn.PRTMD` は **CS（スレーブ）ごとに1つだけ設定するレジスタ**であり、
[04_xspi_boot_and_runtime.md](04_xspi_boot_and_runtime.md) §2.1 で説明したとおり
**マニュアルコマンドモードとメモリマッピングモードの両方がこの同じ設定を共有**します
（マニュアルコマンドの `CDTBUFn` にはコマンド/アドレス/データの**サイズ**設定はありますが、
**ピン幅（プロトコル）を指定する項目はありません**＝36.2.2.8-9で確認済み）。

つまり：

- ある瞬間、そのCSで発行できるコマンドは**全て同じプロトコルモード**（例えば全部1S-1S-1S、
  または全部1S-4S-4S）でなければならない。
- 「制御コマンドは1S-1S-1S、読み出しだけ1S-4S-4S」のように**コマンドごとに動的に混在**
  させることはできず、**`LIOCFGCSn` を書き換えてモードを切り替える**操作が必要。
- モード切り替え前には、[04_xspi_boot_and_runtime.md](04_xspi_boot_and_runtime.md) §2.2
  のとおり**通信を完全停止**（`CDCTL0.TRREQ=0` の確認等）してから行うこと。

## 4. Quad フラッシュ運用時の実践的な設計（推奨パターン）

多くの汎用 Quad SPI NOR フラッシュ（Winbond W25Qxx、Macronix MX25Lxx 等）は、電源投入直後は
**1S-1S-1S でしか応答しません**。Quad I/O 読み出し（`0xEB`）を使うには、多くの場合まず
ステータスレジスタの **QE (Quad Enable) ビット**を立てる必要があります。したがって、
典型的な初期化・運用シーケンスは次のようになります。

1. **`LIOCFGCSn.PRTMD = 0x000`（1S-1S-1S）** に設定。
2. マニュアルコマンドモード（[04_xspi_boot_and_runtime.md](04_xspi_boot_and_runtime.md) §2.6）
   で `RDID`（`0x9F` 等、デバイス確認用）→ 必要であれば `WRSR`（Write Status Register）で
   **QEビットを立てる** → `RDSR` で反映を確認。
3. 通常運転時のコマンド（`WREN`／`RDSR`／`Sector Erase`／`Page Program`）は
   **引き続き 1S-1S-1S のマニュアルコマンドモードで発行**（§2.5-2.6 のとおり、
   書き込み・消去は元々メモリマッピングモードでは実行できない）。
4. まとまったデータを高速に読み出したいとき（起動直後の一段目ローダによる本体イメージの
   コピー等）だけ、通信停止 → **`LIOCFGCSn.PRTMD = 0x090`（1S-4S-4S）に切り替え** →
   `CMCFG1CSn.RDCMD = 0xEB`、`CMCFG0CSn.ADDSIZE` と `CMCFG1CSn.RDLATE`（レイテンシサイクル）
   を**使用するフラッシュのデータシートに記載された `0xEB` コマンドのアドレスバイト数・
   モードバイト・ダミーサイクル数**に合わせて設定 → メモリマッピングモードで連続読み出し
   （memcpy相当）。
   - `0xEB` は一般に「3バイトアドレス＋1バイトのモードビット(M7-M0)＋数サイクルのダミー」
     という構成のフラッシュが多く、RZ/N2L 側には独立した「モードバイト」フィールドが
     無いため、**モードバイト分をアドレスバイト数に含めて `ADDSIZE` を4バイト設定にする**か
     **`RDLATE` 側に吸収する**かは、使用するフラッシュの正確なコマンドフォーマットに応じて
     個別に決める必要があります（本書では一般化できないため、採用するフラッシュの
     データシートを必ず確認してください）。
5. 読み出しが終わったら、以降また制御コマンドを発行する前に **1S-1S-1S へ戻す**
   （手順1に戻る）。

### QPI（4S-4S-4S）は使うべきか

`4S-4S-4S` を使うと**全コマンドがクワッドになり平均スループットはさらに上がります**が、
- フラッシュ側で明示的な「QPIモードへ移行するコマンド」（例: Winbond系 `0x35`）を送る
  必要があり、**移行後は `WREN`/`RDSR`/Erase/Program も含めた全コマンドをクワッドで
  送らなければならなくなる**（モード自体がフラッシュの永続的な内部状態になるため、
  電源を切るかQPI終了コマンド(`0xF5`等)を送るまで元に戻らない）。
- フラッシュの型番によって QPI 対応の有無・移行/終了コマンドが異なり、汎用性が下がる。

このため、**通常は `1S-1S-1S`（制御）＋ `1S-4S-4S`（高速読み出し）の使い分けで十分**であり、
QPI（`4S-4S-4S`）は「特定のフラッシュ品番に固定してよく、かつ制御コマンドも含めた
最大スループットがどうしても必要」な場合にのみ検討する、という位置づけで良いでしょう。

## 5. 書き込み（Page Program）に関する再確認

[04_xspi_boot_and_runtime.md](04_xspi_boot_and_runtime.md) §2.5 のとおり、NORフラッシュへの
書き込みはメモリマッピングモードでは構造的に不可能で、マニュアルコマンドモードで
`WREN → Page Program → ステータスポーリング` を実装する必要があります。Quad フラッシュを
使う場合でも、

- **Page Program 自体は `1S-1S-1S` の標準コマンド（`0x02`）で行うのが最も無難**です
  （§2で述べたとおり、Quad Page Program `0x32` 相当の `1S-1S-4S` は RZ/N2L のプロトコル
  モードに存在しないため）。
- `1S-4S-4S` はコマンドフェーズが1本のままなので、`0x32` を **コマンドとして** 送ること自体は
  可能です。ただし `1S-4S-4S` は**アドレスフェーズもクワッド**である一方、多くのフラッシュの
  `0x32`（Quad Page Program）は**アドレスがシングルでデータだけがクワッド**という仕様
  （＝`1S-1S-4S`）のため、両者は一致しません。`1S-4S-4S` のまま `0x32` を発行すると、
  フラッシュ側が期待するアドレスの入力形式と食い違い、正しく書き込めない可能性があります。
  個別のフラッシュの `0x32` フレーム仕様が実際に `1S-4S-4S` と一致するかをデータシートで
  確認できない限り、**確実な方法は Page Program を常に `1S-1S-1S` で行うこと**です。

## 6. ブートモードとの関係（重要）

- **x1 ブートシリアルフラッシュ（`MD2:0=000b`）は、フラッシュのデータ信号の本数に関わらず
  必ず `1S-1S-1S` 固定**です（[04_xspi_boot_and_runtime.md](04_xspi_boot_and_runtime.md) §1.1、
  マニュアル3.5.4.1）。Quad フラッシュを接続していても、**ブートROMはQuadを一切使いません**。
  Quad モード（`1S-4S-4S`等）は、**ブート後に一段目/二段目ローダが自分で `LIOCFGCSn` を
  再設定して初めて有効になります**。
- x1 ブートで実際にハードウェア上ドライブされる信号は `XSPI0_CKP`、`XSPI0_CS0#`、
  `XSPI0_IO0`、`XSPI0_IO1` の4本のみです（§1.1）。**`IO2`（多くのフラッシュでは`WP#`）・
  `IO3`（多くのフラッシュでは`HOLD#`/`RESET#`）はブート中は xSPI として駆動されません。**
  Quad フラッシュ側がこれらのピンを「通常時はHigh固定でなければ書き込み禁止／ホールド状態に
  入ってしまう」という仕様の場合、**基板側で `IO2`/`IO3` に適切なプルアップを入れておく**か、
  ブート後のソフトウェアが速やかに正しい機能へ切り替える設計にしてください
  （プルアップの要否・レベルは採用するフラッシュのデータシートに従うこと）。
- ブート後、Quad読み出しを使うには **`IO2`/`IO3` に対応する端子の PFC（Peripheral Function
  Control）を xSPI0 機能へ切り替える**ソフトウェア設定が別途必要です（x1ブート時点では
  これらの端子は xSPI0 用に自動設定されないため）。具体的な端子番号・PFC設定値は
  マニュアル「16.6.4 各ブートモードの端子割り当て」および [02_manual_toc.md](02_manual_toc.md)
  の該当ページを参照してください（本書執筆時点では未調査、今後の調査タスク）。

## 7. まとめチェックリスト

- [ ] 採用予定の Quad SPI フラッシュが **`0xEB`（Fast Read Quad I/O）** に対応していることを
      データシートで確認した（`0x6B` Quad Output のみの品番は RZ/N2L のプロトコルモードと
      直接一致しないため非推奨）
- [ ] フラッシュに **QE (Quad Enable) ビット**がある場合、起動時に `1S-1S-1S` の
      マニュアルコマンドで立てるシーケンスを実装した
- [ ] 制御コマンド（WREN/RDSR/Erase/Page Program）は **`1S-1S-1S`** で発行する設計にした
- [ ] 高速読み出し時のみ `LIOCFGCSn.PRTMD = 0x090`（1S-4S-4S）へ切り替え、
      `CMCFG1CSn.RDCMD=0xEB`／`ADDSIZE`／`RDLATE` をフラッシュの `0xEB` フレーム仕様
      （アドレスバイト数・モードバイト・ダミーサイクル数）に合わせて設定した
- [ ] プロトコルモード切り替え前に通信停止手順を踏む実装にした
      （[04_xspi_boot_and_runtime.md](04_xspi_boot_and_runtime.md) §2.2）
- [ ] x1ブート中は `IO2`/`IO3` が未駆動であることを踏まえ、基板側のプルアップ／
      フラッシュの `WP#`/`HOLD#` 仕様を確認した
- [ ] ブート後に `IO2`/`IO3` に対応する端子を xSPI0 機能へ切り替える PFC 設定を実装した
      （具体的端子番号は要追加調査、マニュアル16.6.4参照）

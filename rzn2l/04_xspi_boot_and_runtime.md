# xSPI0 / xSPI1 ブートモード 詳細（ブート時 + ランタイム）

[← README（目次）へ戻る](README.md)

出典: ユーザーズマニュアル「3.5.4 xSPIブートモード（シリアルフラッシュ）」p.97-99、
「3.5.4.3 xSPIブートモードの動作設定」p.99-100、「36. 拡張シリアルペリフェラルインタフェース (xSPI)」p.2089-2143。

対象: `MD2:0 = 000b`（xSPI0 x1ブート）／`001b`（xSPI0 x8ブート）／`111b`（xSPI1 x1ブート）。
RZ/N2L には RZ/N2H のような「セカンドブート CPU 選択」は無く、常に唯一の Cortex-R52 が
ブート処理を実行する（[03_boot_modes.md](03_boot_modes.md)）。

## 1. ブート時の動作（ブート ROM）

### 1.1 使用端子・電気仕様

| 項目 | xSPI0 x1 | xSPI0 x8 | xSPI1 x1 |
|------|----------|----------|----------|
| 使用端子 | `XSPI0_CKP`, `XSPI0_CS0#`, `XSPI0_IO0/1` | `XSPI0_CKP/CKN`, `XSPI0_CS0#`, `XSPI0_IO0-7`, `XSPI0_DS`, `XSPI0_RESET0#` | `XSPI1_CKP`, `XSPI1_CS0#`, `XSPI1_IO0/1` |
| I/O ドメイン | `VDD1833_3`（`MDV3`/xSPI0） | 同左 | `VDD1833_4`（`MDV4`/xSPI1、225FBGAのみ入力ピンあり。121FBGAは常に3.3V固定） |
| プロトコル | **1S-1S-1S 固定** | **8D-8D-8D プロファイル2.0**（HyperFlash等） | **1S-1S-1S 固定** |
| 内部アドレス空間 | `0x6000_0000`〜`0x67FF_FFFF`（xSPI0、CS0+CS1合計128MB） | 同左 | `0x6800_0000`〜`0x6FFF_FFFF`（xSPI1、128MB） |
| 121FBGA対応 | ○ | ✕（非対応） | ✕（非対応） |

### 1.2 ブート ROM の初期設定値（ローダ用パラメータ転送まで）

| 項目 | x1 ブート | x8 ブート |
|------|-----------|-----------|
| CPU クロック (CPU0CLK) | 200 MHz | 同左 |
| xSPI ビットレート (XSPI_CLKn) | **12.5 MHz**（既定。ローダ用パラメータ `ACCESS_SPEED` で変更可） | 同左 |
| サポートコマンド | 読み出し `0x03` | 読み出し（`CA[47:45] = 101b`） |
| コマンド出力 | 1 バイト | 6 バイト |
| アドレス出力 | 3 バイト | 3 バイト |
| ダミーサイクル（レイテンシ） | 0 | 10（`CA[23:16]` からレイテンシサイクルがインクリメント） |
| 初期データ幅 | 1 ビット | 8 ビット |
| プロトコル | 1S-1S-1S | 8D-8D-8D プロファイル2.0 |
| 駆動エッジ | `XSPIn_CKP` の立下がりエッジ | `XSPI0_CKP` の両エッジ |
| サンプリングエッジ | `XSPIn_CKP` の立下がりエッジ | シフトを伴う `XSPI0_DS` の両エッジ |
| フラッシュリセット | ソフトウェア（`0x66` + `0x99`）※x1はハードウェアリセット端子なし | `XSPI0_RESET0#` のハードウェア |

（n = 0 または 1。x8 ブートは xSPI0 のみサポート。）

### 1.3 ブート処理フロー（3.5.1 / 3.5.4 の要約）

1. `XSPIn_CKP`/`CS0#`/`IOx` を上記初期値で有効化。
2. 外部メモリからローダ用パラメータ（xSPI0: `0x6000_004C`以降 / xSPI1: `0x6800_004C`以降）
   を読み出し、`CHECK_SUM` を検証。
3. ローダ用パラメータの `ACCESS_SPEED`／`WRAPCFG_V`／`COMCFG_V`／`BMCFG_V`／`CSSCTL_V`／
   `LIOCFGCS0_V` で xSPI を高速化設定。
4. `LDR_ADDR_NML` から `LDR_SIZE_NML` バイトのローダプログラムを読み出し、`DEST_ADDR_NML`
   （BTCM内）へ展開。
5. Cortex-R52 がそのままローダプログラムへ分岐。

### 1.4 ローダプログラムの配置制約（★重要）

| 項目 | 制約 |
|------|------|
| `LDR_ADDR_NML`（xSPI0内の格納アドレス） | `0x6000_004C`〜`0x60FF_FE00` |
| `LDR_ADDR_NML`（xSPI1内の格納アドレス） | `0x6800_004C`〜`0x68FF_FE00` |
| `LDR_SIZE_NML`（サイズ） | **512バイトの倍数、最大120KB** |
| `DEST_ADDR_NML`（展開先） | **BTCM内 `0x0010_2000`〜`0x0011_FFFF`**（4バイトアライン。Thumbならbit0=1） |

- BTCM全体は `0x0010_0000`〜`0x0011_FFFF`（128KB）。展開先として使えるのは先頭8KB
  （ブートROM予約域と見られる）を除いた**残り120KBすべて**。RZ/N2Hの「一段目ローダは
  最大52KBしか使えない」という制約と比べ、RZ/N2Lは**BTCM自体が大きく（128KB）予約域も
  相対的に小さいため、一段目ローダに最大120KBという大きめの余裕がある**。
- とはいえ、本格的なアプリケーション本体（RTOS＋ユーザーアプリ）をすべて120KB以内に
  収めるのが難しい場合は、RZ/N2H同様に「一段目ローダ（BTCM）が xSPI を自前で読み直し、
  本体（ATCM 128KB や システムRAM 1.5MB）へコピーしてジャンプする」という二段構成も
  引き続き有効な設計パターン。

### 1.5 ブート終了時のレジスタ状態（`xSPI_FLG` に依存）

`xSPI_FLG`（ローダ用パラメータ offset `0x10`）を `0x2236_0679` にすると、ブート終了後に
xSPI の各種設定は**初期値へ戻る**。それ以外の値なら、**ブートで使った高速化設定がそのまま
保持される**。

| レジスタ | `xSPI_FLG = 0x22360679`（初期化） x1/x8 | `xSPI_FLG ≠ 0x22360679`（保持） x1/x8 |
|----------|------|------|
| `WRAPCFG` | `0x00000000` / `0x00000000` | `WRAPCFG_V`（DSSFTCS0[4:0]のみ。フラグ未設定時 `0x00000000`/`0x00001F00`） |
| `COMCFG` | `0x00000000` / `0x00000000` | `COMCFG_V` の設定値 |
| `BMCFG` | `0x00000000` / `0x00000000` | `BMCFG_V`（PREENのみ） |
| `CMCFG0CS0` | `0x00000008` / `0x0000000E` | 同左（x1/x8で初期化有無に関わらず同じ値） |
| `CMCFG1CS0` | `0x00000300` / `0x000AA000` | 同左 |
| `LIOCFGCS0` | 上位16bit `0x0000`(x1)/`0x07FF`(x8) | `LIOCFGCS0_V`（フラグ次第。未設定時 `0x00070000`/`0x000707FF`） |
| `BMCTL0` | `0x00000001` | `0x00000001` |
| `CSSCTL` | `0x00000000` | `CSSCTL_V`（CS0SIZE[5:0]のみ） |
| `SCKCR` | `0x00720606`（初期値） | `ACCESS_SPEED` の設定値（xSPI0: bit6,bit[2:0] / xSPI1: bit14,bit[10:8]のみ） |

**実装上の含意**: 一段目ローダで「本体イメージをもっと速く読みたい」場合は、
`xSPI_FLG ≠ 0x2236_0679` にして高速化状態を維持するか、一段目ローダ自身が §2.2 の
手順で xSPI を再設定する。

## 2. ランタイムでの xSPI 操作（一段目/二段目ローダ、および運用中のフラッシュアクセス）

ブート完了後は xSPI0/xSPI1 は**通常の周辺モジュール**として CPU から自由に再設定・使用できる。

### 2.0 ★ 3 行まとめ（読み出し／書き込み／直接実行の使い分け）

| 操作 | できるか | 方法 |
|------|---------|------|
| **フラッシュ読み出し → RAM（TCM/システムRAM）へのロード** | **できる** | メモリマッピングモードへの単純な逐次読み出し（**memcpy相当**）で足りる。専用ドライバ不要（§2.3） |
| **フラッシュへの書き込み（プログラム／イレース）** | **メモリマッピングでは不可**、別途実装すれば可 | **マニュアルコマンドモード**で `WREN → Program/Erase → ステータスポーリング` を明示的に実装する必要がある（§2.5, §2.6） |
| **フラッシュ上のコードを直接実行（XiP、RAMへロードせず命令フェッチ）** | **技術的には可能**だが**実用上は非推奨** | メモリマッピングモードで直接分岐すれば実行できるが、RAMより1〜2桁遅い。R52のリアルタイム処理には不適（§2.4） |

以下、各項目の詳細。

### 2.1 マニュアルコマンドモード と メモリマッピングモード（36.3）

| モード | 用途 | 主要レジスタ |
|--------|------|-------------|
| **メモリマッピングモード**（XiP的動作） | あらかじめ設定したメモリ領域へのAHBアクセスを自動的にxSPIトランザクションへ変換。**単純な連続読み出し（フラッシュ→RAMへのコピーや直接実行）はこれで足りる** | `CMCFG0/1/2CSn`（アドレスサイズ、`RDCMD`/`WRCMD`、レイテンシ）、`LIOCFGCSn.PRTMD`（プロトコル）、`BMCFG`（プリフェッチ・結合機能） |
| **マニュアルコマンドモード** | イレース／プログラム／ステータスポーリングなど、メモリマップ読み出しでは表現できない任意コマンド（最大4コマンドを連結可） | `CDCTL0`〜`2`、`CDTBUFn`／`CDABUFn`／`CDD0BUFn`／`CDD1BUFn`（n=0〜3） |

対応するプロトコルモード（`LIOCFGCSn.PRTMD[9:0]`）: `1S-1S-1S`, `4S-4D-4D`, `8D-8D-8D`
（xSPIプロトコル指定）に加え、QSPI互換の `1S-2S-2S`, `2S-2S-2S`, `1S-4S-4S`, `4S-4S-4S` にも対応。

### 2.2 設定変更フロー

1. **電圧・アドレス空間設定**: `IOVOLCTL`、`CSSCTL`（CSサイズ）
2. **プロトコルモード設定**: `LIOCFGCSn.PRTMD`
3. **コマンド／アドレスサイズ／レイテンシ設定**: `CMCFG0/1/2CSn`
4. （自動キャリブレーションを使う場合）`CCCTL0CSn.CAEN=0` を確認 → `CCCTL1-7CSn` でコマンド
   設定 → `CCCTL0CSn` → `CAEN=1`

設定変更前に必ず通信を完全停止すること: `CDCTL0.TRREQ = 0`（保留中マニュアルコマンドなし
を確認）。xSPI 全体をリセット/ストップする場合はモジュールストップ機能（低消費電力機能、
`MSTPCRA`）を使用。重大なエラー発生時は `MRCTLA` でモジュールリセットも可能（36.3.5）。

### 2.3 メモリマッピング読み出し・書き込みの仕組み（36.3.3）

- **読み出し**: AHB読み出しアクセスを検出すると、xSPIマスタは即座に読み出しトランザクション
  をxSPIスレーブへ発行する（図36.13）。HBURSTがSINGLE/INCRなら1トランザクション=1xSPIフレーム、
  INCR4/8/16ならバーストサイズ分のAHBトランザクションで1xSPIフレーム、WRAP4/8/16なら2xSPI
  フレームに分割される。
- **書き込み**: AHB書き込みアクセスのペイロードを内部ブリッジバッファに格納し、
  `CMCFG2CSn.WRCMD` で固定されたコマンドと共にxSPI書き込みトランザクションを発行する
  （図36.10）。**1回のAHB書き込みアクセスにつき、固定1コマンドのxSPIフレームが1つ発行される**
  という単純な対応関係のみ（§2.5で重要になる制約）。
- **結合機能**（`BMCFG.MWRCOMB=1`）: 書き込みアドレスがインクリメントで連続している間、
  複数のAHB書き込みを1つの大きなxSPIフレームにまとめてスループットを上げる機能。
  ページ単位で書き込みを要求するデバイス（NORフラッシュ等）に有効（図36.12）。

### 2.4 ★ XiP 実行（メモリマッピングモードでの直接命令フェッチ）は可能か

**結論: 可能。ただし実用上は非推奨。** マニュアル自身が明記している（36.3.3.6）:

> スレーブデバイスの中には、レイテンシを短縮するためにコマンドフェーズを必要としない
> モード（XiPモード）を持つものがある。XiPモードビットを有効にした場合
> (`CMCTL.XIPEN = 1`)、xSPIマスタはレイテンシフィールドにXiP開始コード
> (`CMCTL.XIPENCODE[7:0]`) を挿入し、2回目以降の連続読み出しでコマンドバイト送信自体を
> 省略できる。**この機能はメモリマッピングモードでだけ使用できる。**

つまり CPU の命令フェッチも「AHB読み出しアクセスの一種」として扱われるため、
`0x6000_0000`〜（xSPI0）や `0x6800_0000`〜（xSPI1）のアドレスに直接分岐・実行すれば、
RAM へコピーせずそのまま命令フェッチできる（いわゆる XiP）。

**制約（マニュアル記載の注記）**:
- **XiPモードはスレーブへの一方向アクセス専用**。読み出しと書き込みを混在させることはできない。
- レイテンシフィールドにXiPコードを挿入するサイクルがない設定の場合、XiPコードを挿入できない
  可能性がある。
- プリフェッチ機能（`BMCFG.PREEN=1`）も連続増加アドレスの読み出しを高速化するが、
  **複数のAHBマスタが同じアドレスにアクセスする場合、最新データが読めることは保証されない**
  （最新データが必要なら `BMCTL1.PBUFCLR` でプリフェッチバッファをクリアしてから読む）。

**実用上の指針**:
- xSPI の RAW スループットは仕様上 **200 MB/s**（RZ/N2H の266MB/sより低い）。TCM/システムRAM
  に比べて確実に1〜2桁遅く、**Cortex-R52 のリアルタイム制御ループには不適**。
- ブートROM自身も、xSPIから読み出したローダプログラムをXiP実行せず**必ずTCMへ展開してから
  実行する**（§1.3/1.4）。クリティカルな初期ブートコードでさえXiPを採用していないことは、
  直接実行が性能面で推奨されないことの実例的な裏付けと言える（RZ/N2Hと同じ設計思想）。
- 使うとすれば、大きいが滅多に実行されない読み出し専用コード（非クリティカルなロジック、
  エラーハンドラ、文字列/テーブルデータ等）で、RAM容量の節約を優先したい場合に限定するのが妥当。

### 2.5 ★ 書き込み側: メモリマッピングされたアドレスへの書き込みで NOR フラッシュへプログラムできるか

**結論: できない。** マニュアル36.3.3.2の記述どおり、メモリマッピングモードの書き込みは
「1回のAHB書き込みアクセス → `CMCFG2CSn.WRCMD` で固定された1コマンドのxSPI書き込み
トランザクション」という単純な対応関係しか持たない。これは **OctaRAM/HyperRAM のような
RAM系デバイス**（イレース不要・任意アドレスへ即座に上書き可能）には適合するが、
**NORフラッシュのプログラム／イレース手順とは構造的に噛み合わない**（以下は一般的な
NORフラッシュデバイスの動作仕様との整合性から導かれる結論。マニュアルはxSPI側の
動作のみを規定しており、フラッシュ側のコマンドセットには言及していない）:

1. **Write Enable (WREN) コマンドの前置が必要**: 大半のNORフラッシュはProgram/Eraseコマンドの
   直前に毎回 `WREN`（例: `0x06`）を送る必要があるが、メモリマッピング書き込みは1AHBアクセスに
   つき固定1コマンドしか発行できず、`WREN` を自動挿入する仕組みがない。
2. **イレースの概念が無い**: NORフラッシュは1→0方向にしかビットを変更できず、0→1に戻すには
   セクタ/ブロック単位の事前イレースが必須。メモリマッピング書き込みには「イレース」という
   操作自体が存在しない。
3. **完了待ち（ステータスポーリング）が必要**: Program/Eraseの実行完了まで数十µs〜数百msを
   要し、ステータスレジスタの`WIP`（Write In Progress）ビットをポーリングして完了確認してから
   次の操作に進む必要があるが、メモリマッピングモードにはこの待ち合わせの仕組みがない。

→ **NORフラッシュ（xSPI0/1のブート用フラッシュを含む）への書き込み・消去は、
`36.3.2 マニュアルコマンドモード`（§2.6、`CDTBUFn`/`CDABUFn`/`CDDxBUFn`を最大4つ連結）で
`WREN → Page Program（またはセクタ/ブロックイレース）→ ステータスポーリング` という手順を
明示的に実装する必要がある。** 周期モード（§2.6）を使えば、ステータスポーリング部分は
自動化できる。

なお、**xSPIにOctaRAM/HyperRAMを接続する用途**であれば、上記のイレース/WREN/ポーリングは
一切不要なので、メモリマッピングモードでの単純な読み書きがそのまま使える
（`結合機能`§2.3も参照）。

### 2.6 マニュアルコマンドモード（36.3.2）

2つの機能モードがある。

- **直接モード**（36.3.2.1）: ソフトウェアの設定と要求に従って、xSPIトランザクションを
  **最大4つ連続して発行**できる。一連のトランザクションは1回のトランザクション要求
  （`CDCTL0.TRREQ=1` かつ `PERMD=0`）で発行できる。トランザクション数は`CDCTL0.TRNUM[1:0]`
  で設定（最大4）。`CDTBUFn`/`CDABUFn`/`CDDxBUFn`（n=0〜3）にトランザクション種別・コマンド・
  コマンドサイズ・アドレス・アドレスサイズ・データ・データサイズ・レイテンシサイクルを設定する。
  例: `WREN → Page Program → ...` のような一連のコマンドを1回の要求で発行可能。
- **周期モード**（36.3.2.2）: 期待値ビット（`CDCTL1.PEREXP[31:0]`）とマスク値ビット
  （`CDCTL2.PERMSK[31:0]`）を設定し、読み出しトランザクションを繰り返し発行して**期待値と
  一致するまで自動的にステータスポーリングを行う**機能。Program/Eraseの完了待ち（`WIP`ビット
  ポーリング）の自動化に使える。

### 2.7 パターン制御（36.3.4）— フラッシュリセット等の特殊シーケンス

xSPIフレーム形式以外の任意パターンを送信する機能。`LPCTL0-1.PATREQ` で送信開始。

| パターン | 用途 | 備考 |
|---|---|---|
| XiP禁止パターン | レガシーSPIデバイスのXiPモードを無効化 | `LPCTL0.XD1LEN/XD1VAL/XD2LEN/XD2VAL` で長さ・値を設定 |
| **リセットパターン** | シリアルフラッシュのソフトウェアリセット信号伝達 | `LPCTL1.RSTWID`（CS Low/High幅）、`RSTSU`（データ出力セットアップ時間）。CS幅最小500ns、セットアップ時間最小6ns |
| CSのみパターン | ディープパワーダウンステートからの再開 | `LPCTL1.RSTWID` で長さ設定、CSポートのみ起動 |

xSPI0 x1ブートの「フラッシュリセット: ソフトウェア（`0x66`+`0x99`）」（§1.2）は、実運用時に
ランタイムで同種のリセットシーケンスを再現したい場合、このリセットパターン機能または
マニュアルコマンドモードでコマンドバイトとして直接送出することになる
（`0x66`=Enable Reset, `0x99`=Reset、多くのSPI NORフラッシュの標準コマンド）。

### 2.8 割り込み（36.3.6、36.2.4）

| フラグ | 意味 | 信号 |
|--------|------|------|
| `CAFAILCS0/1` | キャリブレーション失敗 | `XSPIm_INTERR` |
| `CASUCCS0/1` | キャリブレーション成功 | `XSPIm_INT` |
| `BUSERR` | AHBバスエラー（重大。xSPIマスタが初期化される。書き込み中発生時は内部ブリッジバッファがクリアされ、書き込み待ちデータが失われる） | `XSPIm_INTERR` |
| `ECSCS0/1` | ECCエラー検出 | `XSPIm_INTERR` |
| `DSTOCS0/1` | DSタイムアウト（重大。xSPIマスタとスレーブ双方のリセットが必要） | `XSPIm_INTERR` |
| `PERTO` | 周期トランザクションタイムアウト（期待値不一致） | `XSPIm_INTERR` |

割り込み要因は `INTS`（ステータス）／`INTC`（クリア）／`INTE`（許可）レジスタで管理。
CPU0のGIC要求は可能、DMAC起動には使用不可（表36.11）。

## 3. R52 一段目ローダの設計指針（まとめ）

1. ブートROMが展開した一段目ローダ（BTCM、最大120KB）は、**最低限**: クロック概略設定・
   xSPIの高速化（必要なら§2.2で再設定）・二段目イメージの位置とサイズの把握、を行い、
   xSPIの**メモリマッピングモード**で二段目イメージを読み出しコピーする。
2. コピー先は **ATCM（128KB）** または **システムRAM（1.5MB、他バスマスタと共有）**。
3. RZ/N2Lは120KBという比較的大きな一段目ローダ領域が使えるため、RZ/N2Hのような厳密な
   二段構成（52KB制約への対応）が必須ではないケースも多いと考えられるが、アプリケーション
   本体（RTOS＋業務ロジック）が120KBを超える場合は同様の二段構成を検討する。
3. NORフラッシュへの書き戻し（イレース/プログラム）が製品運用上必要（ファームウェア更新等）
   なら、マニュアルコマンドモード（§2.6）のドライバを別途用意する（§2.5のとおりメモリ
   マッピング書き込みでは不可）。
4. 「RAMへコピーせずxSPIを直接実行（XiP）できないか」という設計上の誘惑は、§2.4のとおり
   **技術的には可能だが実用上は非推奨**（R52のリアルタイム性を損なう、RAMより1〜2桁遅い）。
